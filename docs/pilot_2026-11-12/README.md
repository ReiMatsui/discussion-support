# 11月12日の3人試行

**目的は、3人の対面会話でシステムと実施手順が使えるかを確認すること。支援効果を結論する本実験ではない。** 研究者本人と知り合いの2人による1集団なので、介入後の変化を因果効果とは呼ばない。

## 今日やること

1. リポジトリ直下の `.env` の `OPENAI_API_KEY` を有効なキーに更新する。キーはメッセージや記録に貼らない。環境変数側に古いキーを設定している場合はそちらも更新する。
2. `uv run das pilot` で操作画面を開く。開くだけではAPI送信・撮影は始まらない。Chromeで開くことを推奨する。
3. 明日の説明内容を確認してから、画面の「LLM接続を確認する」を1回押す。人工会話を送る既存の使用量制限付き確認を使う。失敗時は表示を確認し、連打しない。
4. 本番と同じ配置で「録画だけ」を20秒試し、保存後に「動画を開く」で3人の声・顔が入るか再生確認する。自分一人で試す場合、記録する人は自分だけとして了承を確認し、他の座席位置からも話して確認する。
5. キー更新後の確認が通っても、音声合成・Soniox・pyannote・実マイクは別途確認が必要。「支援あり」で短い台本を試し、文字起こしとAI音声まで確かめる。

## 起動

```sh
cd /Users/matsuirei/discussion-support
uv run das pilot
```

操作画面は通常 `http://127.0.0.1:8271/`。終了は画面の「終了して保存」、その後「カメラを停止」を押し、ターミナルで Ctrl+C。録画中は画面を閉じない。Macを電源につなぎ、画面ロック・スリープを避ける。

- **台本確認**：最大5分。明示的な採否提案、既出理由の提示、補足への応答を確認する。
- **自由議論**：最大8分。役割カードを配り、架空の仕事体験先を1社決める。
- **録画だけ**：ブラウザのカメラ・マイクだけを使用し、ASR・LLMに送信しない。
- **無支援・文字起こし**：ASR等の外部送信はある。無送信のモードではない。

画面には共有の企業情報だけを出す。私的な役割カード・得点表をAIに与えない。会話ログ画面は操作確認用とし、自由議論中に参加者へ読み上げない。既出理由の表示自体も介入の一部なので、後の正式実験では表示条件をそろえる。

## 30分の進め方

|時間|作業|
|---|---|
|0–5分|目的と記録・外部送信の説明、了承、座席と音量の確認|
|5–8分|20秒の録画だけを行い、映像と全員の声を再生確認|
|8–13分|台本確認。文字起こし開始を確認してから読む|
|13–15分|各自が自分の役割カードを読む。台本の意見は引き継がない|
|15–23分|自由議論、全員が受け入れられる1社を決める|
|23–30分|保存・再生確認、短い聞き取り、問題の時刻を記録|

準備が遅れたら自由議論を短くせず、台本の後半を省く。AIの準備に2分以上かかる場合は開始せず原因を確認する。30分以内に直らなければ録画のみの議論と手順確認に切り替え、**AIの動作確認は未達**と記録する。

## 使用量の制御

- 接続確認：既存の `bounded_probe` をそのまま使う。累計3回、既存の費用見積もりによる送信前制限を継承。今回の作業では実APIを呼んでおらず、台帳をリセットしていない。以前の失敗も回数に含む。
- 試行本体：各回 **LLM判定60回まで**。台本5分／自由議論8分で自動終了。ブラウザが止まった場合はサーバー側も上限の20秒後に停止を試みる。
- 60回は判定の呼出回数。既存通信処理に互換性対応の再送が1回あるため、HTTP送信数の厳密な上限ではない。金額上限でもない。音声生成・Soniox・pyannote等の料金は別。十分な利用枠を確認し、終わったら必ず停止する。
- 動画は約1Mbps指定、512MiB上限、1チャンク16MiB上限。保存先に1GiB以上の空きが必要。

## 保存されるもの

`transcripts/pilot/<起動日時>/<試行日時>/` に分けて保存する。

- `camera.webm` または `camera.mp4`：映像とブラウザマイクの音声。AI音声は室内のスピーカーからマイクで拾う。必ず再生確認する。
- `video.json`：保存完了・チャンク数・バイト数。`complete: false` は未完了。ファイルが存在するだけで成功と判断しない。
- `round.json`：設定、開始・終了時刻、停止理由、本体終了コード。
- 文字起こしを使った回：`conversation.wav`、`conversation.md`、`conversation.turns.jsonl`、`conversation.diag.jsonl`、`conversation.study.jsonl`、本体設定・コンソール記録等。
- 起動日時の直下に `pilot_events.jsonl`：観察ボタンと時刻、操作エラー、各回の開始終了。

ブラウザ録画と音声本体は開始時刻が少し異なる。最初に「台本確認、開始です」等を発声して両方の記録に目印を入れる。厳密なフレーム同期は実装していない。

## 今日確認できたこと・まだできていないこと

人工映像・人工音声によるブラウザ録画、順序付き保存、再生、再読込時の停止と未完了保存を確認済み。ユニットテストでは認証前の支援起動抑止と呼出回数上限を確認した。**実API・実機の3人録音・AI音声・人への有効性は未確認。** 接続確認はテキストLLMのみで、音声モデルの利用可否まで保証しない。

この議題と得点は今回作成した試行用であり、妥当性が確立した交渉課題の転載ではない。実験者の参加、知り合い同士、台本後の順序効果、架空得点への動機づけ不足がある。短時間で合意しても、介入機会がなければそのまま記録する。効果を出すために途中で得点・ルールを変えない。
