# 実験モードの検証記録

2026年11月3日

## 確認したこと

- 新しい採否支援モードを、旧来の脱線・事実確認・参加への声かけと分けて接続した。通常起動の既定モードは変更していない。
- 無支援条件ではLLMの意味抽出、AIの音声、参加者向け理由記録が動かないことを人工入力で確認した。
- 引用が実在すること、対象案、時系列、検討の根拠、古い出力の破棄、提示回数・間隔・有効期限を検査する。
- 認識結果や話者が変われば古い表示を消し、新しいスナップショットを評価する。相づち・無応答を確認済みにしない。
- 音声エージェントへ短い読み上げ文を渡す経路、指示なく生成した音声の抑制、古くなった最初の音声の破棄を模擬通信で確認した。
- 参加者用の `/study` と `/api/study` をローカルHTTP通信で確認した。得点表や未発言の役割資料は含めていない。
- 実際のAI発言は従来の転記に加え `.study.jsonl` のvoice_deliveryとして残す。読み上げ予定文の送信だけでは、実際に聞こえたと認定しない。

## 実接続の結果

人工会話1件を用いた実LLMへの接続を試みたが、この実行環境のAPI設定ではHTTP 401で失敗した。モデルは既存設定のgpt-5.4-mini。キーの値は保存していない。現在の実装で利用できるモデル・キーの組合せや、実際の意味抽出性能は確認できていない。認証エラー本文にキーの一部が含まれる場合があるため、その本文を端末や保存ログへ出さないよう修正した。

## 実装上の具体化と限界

- 文面は、LLMの自由な整文ではなく、抽出された引用と短い定型文から構成する初期実装とした。LLMには採否提案・理由・関係・関連性の意味判定を担当させる。文面の柔軟さの効果は評価していない。
- 理由を必ず1件に固定せず、関連性順を保って文字数内に収まる引用を提示する。先頭の引用すら入らなければ棄権し、引用を途中で切ったり一般的な問いに差し替えたりしない。
- 文長160字と候補有効期限15秒は未検証の試作値。1.2秒の無音、上限2回、同一案60秒間隔も最適値ではない。本実験前に設定と版を固定する。
- 同時に複数の採否提案が新しく入った場合、現在有効な一つをLLMが選ぶ初期実装である。提案の取りこぼしと棄権は予備試行で調べる必要がある。
- 引用の実在は意味の正確さを保証しない。引用の切り取り、扱う案、同内容の認定、関連性、検討済みの分類は、人が原音と根拠を確認する必要がある。
- 全二重モデルの停止遅延、音声の読み上げ忠実度、ASR・話者訂正の影響、モデル遅延、20分での負荷、介入による人の反応は未検証である。

人の募集・録音・予備試行、倫理審査、報酬の決定は実施していない。
