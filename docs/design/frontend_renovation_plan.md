# フロントエンド改修 設計計画

ブランチ: `feat/frontend-renovation`

## 目的（ユーザー要望）

1. **起動/停止が Ctrl-C しかない** → ブラウザから「停止」できるように。
2. **UIが大ざっぱで見にくい** → ちゃんとしたWebアプリに作り直す。
3. **エージェントモードが分かりにくい** → 3つのモードを分かりやすく、実行中に切替可能に。

## 決定事項（確認済み）

- **作り方**: Webアプリに作り直す（現状の2秒ごと全リロードHTMLを脱却）。
- **起動/停止**: 停止のみUIから（起動はコマンドのまま）。
- **モード切替**: 実行中にUIから3モードを切替（AIパートナーの接続/切断を含む）。

## 3つのモード（再定義）

| UI名 | 内部 | 構成 |
|------|------|------|
| 議事録のみ（話者分離） | `transcribe` | エージェントoff・パートナーなし。文字起こし＋声紋分離だけ |
| AIと会話（会話中にファシリテート） | `converse` | AIパートナー接続＋ファシリテーター介入 |
| 人間同士に介入 | `facilitate` | ファシリテーター単体（S1-S5）。議題は明示or冒頭自動検出 |

`converse` と `facilitate` の違いは **AIパートナーの有無**。実行中切替では
パートナーを動的に connect()/close() する。

## 現状（出発点）

- ライブUIは `write_html` が生成する静的HTMLを `_UIHandler`(HTTPサーバー)が配信。
  `<meta refresh=2s>` で全リロード。サイドバーに話者/統計/論点/エージェント設定。
- 制御は POST `/rename` `/activate` `/agent`。停止は無し（Ctrl-Cのみ）。
- `live_transcriber.html`（別の単体文字起こし）と Streamlit（評価ビューア）は
  本改修の対象外。

## 技術方針

- **単一ファイルSPA**（ビルド不要）を推奨。`index.html` に最新JS（バニラ or
  軽量フレームワークをCDN）で構成し、Python HTTPサーバーがJSON APIと共に配信。
  - 利点: ビルドパイプライン不要・配信が単純・研究プレビューに適する。
  - 代替: React等でビルドする本格SPA（綺麗だがビルド前提。必要なら後で移行）。
- ライブ更新は **SSE（Server-Sent Events）** で差分配信（全リロードを廃止）。

## 進め方（小ステップ・テスト付き）

### F1: バックエンドAPIの土台
- `_UIHandler` を拡張し、JSON APIを用意:
  - `GET /api/state` … 議事録・話者・統計・論点・参加度・現在モード・稼働状態
  - `POST /api/stop` … `state.stop` を立てて graceful 終了
  - `POST /api/mode` … モード切替（F3で本実装、まず枠だけ）
  - 既存 `/rename` `/activate` `/agent` は維持
- まずは既存HTMLを残したまま API を追加（並行運用）。テスト: APIのレスポンス。

### F2: ライブ更新（全リロード廃止）
- `GET /api/stream`（SSE）で発話追加・状態をプッシュ、または軽量ポーリング。
- フロントは差分で議事録を追記。`<meta refresh>` を廃止。

### F3: 実行中モード切替（3モード）
- セッションに `set_session_mode(mode)` を実装。エージェントon/off＋パートナーの
  connect/close をオーケストレーション。パートナーを動的生成できるよう、生成に
  必要な設定（api_key/voice/topic）をセッションが保持。
- マイク音声ルーティング（`_run_from_mic` の echo判定等）がパートナー有無の
  動的変化に追従することを確認。
- API `POST /api/mode {mode}`。テスト: モード遷移のオーケストレーション。

### F4: SPA本体（Webアプリ）
- 単一ページUIを構築:
  - 上部: モードセレクタ（3モードを明確なラベル＋説明）、稼働状態、停止ボタン
  - 中央: ライブ議事録（差分追記、話者色分け、介入を強調）
  - サイド: 話者/名前登録、参加度・発言量、論点
- 見やすいタイポグラフィ・余白・レスポンシブ。

### F5: 仕上げ・レスポンシブ・モバイル
- 細部の調整、配色、ダーク対応（任意）。

### F6: テスト・ドキュメント
- API/モード遷移のユニットテスト。
- README/COMMANDS を更新（モード別の起動コマンド、UIからの停止）。

## 推奨着手順

F1（API土台）→ F2（ライブ更新）→ F3（モード切替）→ F4（SPA）→ F5（仕上げ）→ F6（テスト/Docs）。
F1〜F3はバックエンド中心で堅実に、F4で見た目を一気に刷新する。各ステップでテストを緑に保つ。

## スコープ外（今は）

- ブラウザからの「起動」（常駐デーモン/ランチャー）。
- `live_transcriber.html` 単体ツール、Streamlit評価ビューアの刷新。
- 認証・複数同時セッション。
