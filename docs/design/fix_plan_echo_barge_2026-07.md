# 修正計画書: 介入被りとAI音声の話者混入（2026-07-02 セッション 16:42 の障害解析）

実施者向け。着手前に `docs/HANDOVER-2026-07-02.md`（環境・テスト実行・品質基準）を読むこと。

## 0. 観測された障害（transcripts/2026-07-02_1642.*）

タイムライン復元（音声ms0 ≈ 16:42:53）:

1. 参加者Aが 00:13.6〜00:24.8 の長い発話中（11秒）、その途中の 16:43:13 に manual_call（音声呼びかけ「次の進行」）が pause_act=1.025s で発火 → **AIがAの発話に被せて話し始めた**
2. Aの発話継続により自動interruptでAI発話は中断。中断までに再生された冒頭「まず、今日の目的と決め…」がマイクに回り込み、STTが 00:25.0〜26.9 の発話として確定
3. この漏れ込みは声紋で誰とも一致せず（sim=-0.097）**新規匿名話者 #2 として蓄積開始**（diag 00:25, kind=蓄積中）
4. その後のAI発話（沈黙要約, 16:45:22〜）の漏れ込みも #2 に蓄積され、累積文字数が閾値を超えた 02:42 時点で **#2 が「参加者B」として自動登録**（議事録に「追跡開始」通知）。テキスト自体は安全網エコー除去で落ちたが、**登録の副作用はエコー判定より先に済んでいた**
5. 遡及リネームにより 00:25 の漏れ込みレコードが「参加者B: まず、今日の目的と決め。」として議事録に残存。以後、AIの声が参加者B（幻の参加者）として追跡され続ける状態になった

## 1. 根本原因（3つ、独立）

### D1: 中断されたAI発話がエコー参照に残らない
`agents/_realtime.py` の `interrupt()`（:504〜）は `_ai_text_buf`（ここまで喋った転写）を**リトライ用には保存する**が、エコー除去の参照 `_recent_ai_texts` には積まない。`response.done`（:267）で `_ai_text_buf` はクリアされる。このため中断発話の「実際に再生された冒頭」がテキスト安全網（`_recv_loop.py:179-194` の `_best_similarity`）の照合対象に存在せず、漏れ込みが素通りする。00:25 の混入の直接原因。

### D2: 声紋トラッカーの副作用（蓄積・自動登録）がエコー判定より前に走る
`_recv_loop.flush()` の処理順が「`tracker.classify`（文字数蓄積・自動登録・追跡開始通知まで実施, :98-126）→ AI声紋エコー除去（:104-113）→ テキスト安全網（:179-194）」の順。テキストが最終的にエコーとして破棄されても、**破棄されたはずの音声で匿名話者の蓄積・自動登録が完了してしまう**。02:42 の「参加者B」誕生の直接原因。なおAI声紋（`AI_VOICE_KEY`, 再生PCM 3秒から自動登録）はマイク経由の室内音響を通った声とは埋め込みがずれ、AI_THRESH（redimnet 0.50）を下回って素通りしうる — AI声紋照合だけには頼れない。

### D3: 発話中の被り（barge-inのフロア判定）
manual_call は pause 1.0s で発火するが、人間は発話の途中で1秒程度の間を普通に置く。16:43:13 の発火は Aの発話途中の自然な間（pause_act=1.025s）を「フロアが空いた」と誤認した。M6対策（partial受信でタイマー更新, コミット 4024a70）はこれを緩和するはずだが、**このセッションのプロセスが 4024a70 を含んでいたかは未確認**（マージ 16:33 の9分後のセッション。プロセス再起動のタイミング次第）。また partial の更新間隔が疎な区間では、タイマー方式だけでは1秒の隙間が生じうる。

## 2. 修正内容（3コミット）

### F1 `fix(live): 中断されたAI発話をエコー参照に残す`
- `agents/_realtime.py` `interrupt()`: `delivered = self._ai_text_buf.strip()` を取った直後、非空なら `self._recent_ai_texts.append(delivered)` する（発話済み冒頭こそがマイクに漏れた音声なので、参照として最重要）
- `response.done` ハンドラ（:267 で `_ai_text_buf=""` する箇所）: `_interrupted` 中で buf 非空なら同様に `_recent_ai_texts` へ退避してからクリア（cancel時に transcript.done が来ない場合の保険）
- `transcript.done`（:258-262）は既に interrupted でも `_recent_ai_texts` に積むので変更不要。**重複appendは害がない**（照合参照が増えるだけ）が、直近と同一文字列なら省く程度の重複回避は入れてよい
- テスト: interrupt後に `_best_similarity("まず今日の目的と決め")` が高くなること（既存の realtime テストのフェイクWS基盤を流用）

### F2 `fix(live): エコー判定を声紋トラッカーの副作用より先に評価する`
`_recv_loop.flush()` の再構成:
1. **テキスト安全網（現 :179-194）を `tracker.classify` より前に移動**する。判定に必要なのは `cur_text` と agent/partner だけで、依存はない。エコーと判定したら classify を呼ばずに破棄（= 蓄積も登録も起きない）
2. **エコー窓中は登録系の副作用を抑止**: `tracker.classify(...)` の呼び出しで、`agent が ai_speaking または in_echo_window`（partnerも同様）の間は `count=False` を渡し、文字数蓄積・自動登録をさせない（話者判定自体は行う）。室内音響でAI声紋照合が外れた漏れ込みが「新規話者の蓄積」に化けるのを塞ぐ。正当な人間発話の登録がエコー窓ぶん遅れるのは許容（登録は累積制なので影響は軽微）
3. AI声紋エコー除去（`__..__`）は現位置のままでよい
- 注意: テキスト安全網の移動により、これまで安全網より前に書かれていた diag（:198-204）との順序が変わる。**エコーで破棄した発話は diag に「echo_drop」として1行残す**ようにする（今回の解析で「記録が無いのに登録通知だけある」状態が追いにくかったため。type="echo_drop", sim, 対象テキスト40字）
- テスト: (a) エコー窓中に配信済みAIテキストと類似の発話が来たとき、classify が呼ばれず（または count=False で）匿名話者が増えないこと (b) echo_drop が diag に残ること (c) エコー窓外の通常発話の登録挙動が不変であること

### F3 `fix(live): アクティブなpartialをフロア占有として扱う`
- `SessionState.show_partial` は partial_text を保持している。agent worker のフロア判定（barge-in/通常の両レーンで silence_elapsed を計算している箇所）で、**`state.partial_text` が非空なら silence_elapsed を 0 とみなす**（state_lock 下で読む）。「誰かの発話が今まさに転写されている＝フロアは埋まっている」の直接表現で、タイマー更新間隔の疎さに依存しない
- partial はフラッシュ/空更新でクリアされる（stale化しない）ことを確認した上で実装。万一に備え「partial が 10秒以上変化していなければ無視」のガードを入れる（`show_partial` で変化時刻を記録済みのはず。無ければ `_last_partial_change` を追加）
- 既存テスト（retry/silence系）への影響を確認。FakeState に `partial_text=""` を追加
- テスト: partial 非空の間は fact/manual candidates が awaiting_pause で抑制され、partial クリア＋pause経過後に発火すること

### 実施後の手動確認（ユーザー向けメモ）
- **プロセスを必ず再起動してから**再現テスト: 長めの発話の途中で「AIさん、〜して」と呼びかけ、(a) 発話中にAIが被せてこない (b) 中断が起きた場合もAI発話の断片が議事録に入らない (c) 新規参加者の「追跡開始」が誤発生しない、を確認
- なお D3 の残余（本当に1秒黙ってから話を再開する人）には F3 は効かない。検証（S3）で被り率がまだ基準超えなら manual の pause を 1.0→1.5s に上げる（`_KIND_POLICY` 1箇所の変更）

## 3. スコープ外
- AI声紋の照合改善（室内音響対応のための再生音声でなくマイク回り込み音声からの登録）— F1/F2 で足りるか検証してから
- 幻の参加者を事後に削除するUI — 今回は発生自体を防ぐ。既存セッションの participants 修正は手動リネームで可能
- 議事録に「ファシリテーター（中断）」として途中発話を残す仕様 — 研究上は delivery ログ（interventions.jsonl）に完全な記録があるため不要と判断
