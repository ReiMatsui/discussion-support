# 実験前の動作検証（2026年11月5日）

## 現在の判定

**人工入力による制御・記録・表示の検査は通過した。ただし、実際のLLM接続が401で失敗しているため、人を対象にした実験を開始できる状態とは判定しない。**

今回の確認は研究用の採否判断支援モードを対象とする。提案手法や課題を別案へ変更する作業ではない。録音、マイク入力の送信、音声の実再生、参加者募集は行っていない。

## 不具合の再現と修正

追加した次の3テストは、修正前にはいずれも失敗した。

|状況|修正前の問題|修正|
|ASRの途中経過が届かず、確定した発言だけ届く|古い途中経過の時刻から無音時間を計算し、確定発言の直後でも処理を開始した|確定記録の変化を観測した時刻からも待つ。発言内容・話者の訂正にも適用する|
|音声指示を送信している間に人の訂正が届く|送信前の記録だけを使い、古い候補を有効な発話要求として計上した|送信直後も記録と途中経過を再取得し、変化があれば停止を要求し、提示回数を消費しない|
|音声指示の送信処理が長引く|送信前の時刻で有効期限を判定し、期限切れの要求を計上した|送信に要した時間を含む時刻で確定判定し、期限切れなら停止を要求する|

送信後の検査は、送信済みの音声指示そのものを取り消せる保証ではない。検出から実際に音声が止まるまでの遅延は実機で測る必要がある。ASRに一切現れない発話も検出できない。

意味抽出は人工の正解データを返す関数に、音声送信は記録だけを行う関数に置き換えた。各条件に240発話・120回の採否提案を投入し、0.1秒刻みで12,001回処理した。実時間20分の耐久試験ではない。

|支援あり|120回|12回|6案それぞれ2回|期待値と一致|
|無支援|0回|0回|消費なし|期待値と一致|

通常の待機1.2秒、同一案60秒間隔、同一案2回上限を有効にした。要求はすべて有効な候補として確定された。ログは各条件約1.5〜1.6MB。語義の正確さ、LLMの実遅延・費用、音声の忠実さ、実験での介入頻度、効果を測ったものではない。

個別の自動テストでは、古いLLM結果の破棄、話者訂正、発話中の抑制、通信のタイムアウト・切断後の次の入力での回復、送信拒否時の候補失効、認証失敗後の繰り返し要求停止も確認した。通信失敗時に同じ入力を自動再送する仕様にはしていない。引用の実在・取り扱い済み根拠の検査、条件変更の拒否、参加者用HTTP画面も既存のテストに含まれる。
