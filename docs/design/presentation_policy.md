# 提示ポリシー設計：議論グラフ → エージェントが出す「一言」

最終更新: 2026-06-01
担当: Rei

## 0. このドキュメントの主張

議論グラフ (AF) は内部表現として複雑なまま持つ。**ユーザーに見せるのはグラフではなく、エージェントが選び取った最小の介入 (一言)** である。
したがって研究の焦点は「グラフの可視化」ではなく **「グラフのどの構造シグナルを、どの介入に、どの形で変換するか」という選択ポリシー** にある。

提示の良し悪しは次の 3 段の対応で決まる:

```
AF 上の構造パターン  →  介入タイプ (発話行為)  →  提示の形 (誰に・いつ・どう)
```

「4 層 (L1〜L4)」という固定の括りは廃し、後述の **直交する 2 軸 (誰に × いつ)** で提示先を決める。

### 設計上のポイント

- **2 と 4 は別物**: 2 は「あなた個人が応答を落としている」(対個人・応答性)、4 は「議論全体が片寄っている」(対全員・バイアス)。検出も宛先も違う。
- **5 が貢献①②④の本丸**: 「同じ事実が対象主張ごとに支持/攻撃に変わる」evidence 設計が活きるのはここ。外部知識を"関係ラベル付き"で議論に接続する介入。
- すべて **「事実 (evidence) のスタンスは対象主張ごとのエッジで決まる」** 前提。提示文も「Xはこの主張に対して反論になる」と必ず対象主張を添える。

## 2. 提示先の決め方：「4 層」を捨てて 2 軸で

旧 L1〜L4 は「誰に」と「いつ」を畳み込んでいた。直交させると提示の"形"が自動的に決まる。

| | **議論中 (in-flow)** | **区切り (breakpoint)** | **議論後 (post-hoc)** |
|---|---|---|---|
| **個人** | 手元デバイスに 1 行のグランス通知 (パターン 1,2) | 個別の短い問いかけ | 個別ミニグラフで振り返り (反応しなかった論点 等) |
| **全員 / ファシリテータ** | (原則出さない — 発話を遮らない) | 一文の俯瞰サマリ / 反対側の事実 (パターン 4,6,7,8) | 全体グラフの可視化レビュー |

原則:
- **対面では人は喋っている → 議論中にグラフ図は出さない**。出すのは個人宛の 1 行だけ。全員向けは区切りで一文。
- **グラフ図そのものは「ファシリテータ常時画面」か「事後レビュー」に限定**。構造の恩恵は、参加者には"選択された一言＋関係ラベル"として間接的に届ける。
- これにより、テキスト⇄音声⇄対面いずれのモダリティでも同じ判断ロジック (AF 状態のみ依存) が使える。

## 3. 複数パターンが同時に立ったときの調停

`decide_intervention` は毎ターン 1 つの `InterventionDecision` を返す。優先順位:

1. **新規性ゲート**: 前回介入後に新エッジが無ければ SKIP。
2. **重大度順**: 見せかけの合意(8) > 偏り(4) > 未応答の攻撃(2) > 橋渡し(5) > 隣接(1)。停滞(7)は他が無いときの既定経路。
3. **抑制間隔**: 同種の全員向け介入 (L2系) は `l2_min_interval` ターン空ける。個人通知は `max_items=1〜2` に制限。
4. **宛先の分散**: 同じ人に連続で通知しない (特定参加者への介入集中を避ける)。

---

## 4. 関係ラベルの強度 (Phase 2 で振る軸)

同じ介入でも"言い方"で効果が逆転しうる (直球のラベルは防御反応を生む)。3 段階を ablation 候補にする:

- **直球**: 「これはあなたの主張への〈反論〉です」
- **機能ラベル**: 「コスト懸念に答える事実があります」
- **顔を立てる自然文**: 「Aさんの論点をさらに確かめるなら、こんな事例があります」

これは `comparison_execution_plan.md` の Phase 2 (presentation variation) の「関係ラベルの強度」次元に対応。RQ2(反対意見理解) と RQ3(納得感) でトレードオフが出る可能性。

---

## 5. 実装への落とし込み (次の一歩)

- 現状 `reason ∈ {adjacent, balance_correction, stage_alignment}` を、上表の 8 パターンに拡張 (`unanswered_attack` / `bridge_evidence` / `revive_minority` / `premature_consensus` を追加)。
- 各パターンは `BiasReport` / `StageReport` と同様、**AF から決定的に検出する純関数**として書く (テスト容易・LLM 不要)。
- LLM は最後の「提示文の自然文整形」だけに使う (パターン判定には使わない)。
- 介入ログ (`data/runs/<run_id>/interventions.jsonl`) に `pattern` フィールドを足し、「どのパターンが何回・誰に発火したか」を集計 → これ自体が RQ3(透明性) と提案手法の説明可能性の証拠になる。
