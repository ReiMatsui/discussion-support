unregistered_speakers.md`、§1〜§44）は経緯の記録で、追記のみ・訂正も追記で

## 3. 測って却下したもの（再提案しない。理由は括弧の節）

- 問い合わせ音声への文脈付加（ラベル/上流キーの過去2〜10秒）——全条件で悪化。
  短い発話では足した側が埋め込みを支配する（§36）
- Soniox の区切りを話者境界で割り直す——上限が 0.2pt しかない。「またぎ」の
  実体の 9割は同時発話で、区切りでは分けられない（§37）
- b3 / b6 への変更——b3 は効果なし、b6 は b5 と同等で1.5倍遅い（§38）
- 単純方式への人数の付与（固定・上限とも）——悪化。割りすぎは安く混ぜるのは
  高い（§41）
- 上流キーのクラスタ統合（rekey 方式）——悪化。上流の誤対応を固定化する（§44）
- 席ルールのオフライン再現（simulator）——記録と88.9%しか一致せず、測定の
  土台にならないので廃棄（§40.1）

## 5. 測り方の規約

- 再生・採点は `eval/_pipeline.py` **だけ**を使う。書き写すと必ずずれる
  （§29・§34 で実際にずれた）
- 正解の当て方は `align="text"`（§34）。時間の重なりは、重なりの多い＝難しい
  場面を分母から落とすので使わない
- 件数と文字数を**両方**出す。片方では判断を誤る（§34.4）
- 採点できた割合を併記する。落ちた分に偏りがあると数字が化ける（§34.5）
- 「〜を使わない」条件を作るときは、**依存をコードで確かめる**。設計上の
  正当化と実装の依存は別物（§44.5）
- 発話ごとの声紋は `eval/_utt_embeddings.py` が `eval/_emb/` に保存している
  （b5・text整列。再計算は9本で15分かかる）

## 6. データの現状と限界

- GT があるのは千葉コーパス（3人・雑談）13本ぶんの再生ランのみ。
  **フォーマルな会議・4人以上・実マイクの検証データは1本も無い**
- 2026-07-14_142016（実マイク）は録音ずれ（§30。修正済みだが記録は旧形式）
  と内容（雑談の動画収録）の両方で比較の土俵に乗らない（§42.2）
- 2026-07-20 以前の記録には `ov`（重なり検出）と `src`（決定経路）が無く、
  その断面は読めない
- 残る誤帰属の本丸は同時発話（発話時間の24.8%が重なり）。区切りでも声紋でも
  届かず、音源分離が要る（§37）
