# 一人リハーサルの手順（人を集める前に通す）

目的: 移行後のシステムを、実マイクと内蔵スピーカーの条件で一人で通し、
「人を集めたときに起こる失敗」を先に潰す。所要 40〜60 分。
記録はすべて `transcripts/<日時>.log`（ターミナルの写し）、`.md`（議事録）、
`.interventions.jsonl`（介入ログ）に残る。終わったら Claude に「終わった」と
言えばログを読みに行く。

準備: 静かめの部屋、ノート PC を机の中央、ブラウザ UI を開く。
名前を登録して始める（声かけの宛先が「参加者C さん」にならないように）。

## A. 音響リハーサル（20 分）: `--sim-acoustic`

```bash
uv run python -m das.asr.live --simulate 'AIツール導入の是非' --sim-scenario derailed --sim-acoustic
```

参加者の声はスピーカーから鳴り、STT・話者分離・GPT-Live へはマイクで拾った
部屋の音が入る。本番との差は「相手が人間か」だけ。

| # | すること | 合格の見え方 |
|---|---|---|
| A1 | 何もせず 2 分聞く | 議事録に参加者 A/B/C の行が付き、AI の声が参加者として混ざらない（`# … 声紋を登録しました` の後、`echo_drop`／声紋一致で落ちる）。UI の「未確定」が増え続けない |
| A2 | 脱線して 45 秒ほど待つ | `# [drift] 判定: ××× 離れている時間=…` が増え、`脱線が45秒以上続いています` → 進行役が議題へ戻す一言（`[ファシリテーター]:` の行）。`→IDLE` 行の「尽き」が 0〜1 回 |
| A3 | 進行役が話している最中に「ちょっと待って」と被せる | 進行役が文の途中で止まる。ログの `→IDLE` 行で声の長さが短い。議事録に自分の「ちょっと待って」が残る（消えない） |
| A4 | 「ファシリテーター、ここまで整理して」と呼びかける | 1〜2 秒で答える。`[voice] ファシリテーター呼びかけ検出` の後に `呼びかけには直接応答済み（再送しない）` が出て、二度は言わない |
| A5 | 「黙って」と言う | 「はい」程度で止まる。以後、呼びかけ以外で口を挟まない（`unrequested_turns` が増えない） |
| A6 | UI で「介入オフ」→ 30 秒 → 「介入オン」 | オフの間は `[trigger]` が出ない。オンに戻して脱線を続けると再び戻す |
| A7 | UI で声を cedar に変える | `設定を反映（… 開き直し NNNms）` が出て 3 秒以内。次の発話が新しい声。旧声のエコーが人の発言として残らない |
| A8 | UI で「新しい会議」 | 議事録が空になり、続けて話すと新しい行が付く。`話者分離が停止` の警告が出ない。前会議の続きを進行役が話さない |
| A9 | Ctrl+C で終了 | `Ctrl+C を受信。議事録を保存して安全に終了します…` → 数秒で終わる（kill しない） |

## B. 耐久（30 分・放置）

```bash
uv run python -m das.asr.live --simulate 'AIツール導入の是非' --sim-scenario healthy
```

30 分後に停止。ログで `再接続` `立て直し` `取り消し` `予期しないエラー` を
数える。0 が理想、1〜2 なら原因を見る、繰り返していれば止める前に Claude に送る。
`intervention_review.jsonl` が数 MB を超えていないことも見る。

## C. 二人試行（10 分 × 1〜2 回）

研究室の誰か一人と、議題を決めて普通に話す。標準プロファイル。
見るのは A と同じ項目に加えて、介入が「早い／遅い／的外れ」のどれだったかを
終わってから二人で 3 段階で言い合い、`replay` の Live チップ（指示→声の遅延、
指示なし発話、重なりと黙るまで）と突き合わせる。

```bash
uv run python -m das.asr.live.replay transcripts/<日時>.turns.jsonl --no-api --serve
```

## 判断

A の 9 項目が通り、B で繰り返しの異常が無ければ、3 人を集めてよい。
A3・A4・A5 のどれかが通らないときは、集める前に直す（GPT-Live の指示文か
エコー除去の問題で、人が増えても解決しない）。
