# 設計書: 採否込みリプレイ（replay v2）

実施者向け。根拠: `docs/review-2026-07-02/01_live_pipeline.md` M5。目的: **介入ロジックの改良（価値ゲート・閾値・ポリシー変更）を、実会議なしで過去の turns.jsonl に対して反復検証できる**ようにする。H1統合（`af_live_integration_2026-07.md`）後の改良ループの基盤なので、フェーズ4以降と並行して用意する価値が高い。品質基準は共通。

## 問題

現 replay は checker（候補生成）だけを、live と異なる周期規則（`n % INTERVAL == 0` 等）で回す。FacilitationController の採否・pause/cooldown・hold・TTL は再現されないため、「replayで候補が出た」と「liveで実際に喋る」が一致せず、閾値調整の結論が live に転移しない。

## 設計

### R1 仮想クロック駆動の採否シミュレーション（新モード `--arbitrate`）

- turns.jsonl の各レコードは ms を持つ。**仮想クロック**を ms で進めながら、以下を live と同じ駆動条件で回す:
  - checker 相当: 候補投入は「記録済みの判定を再生」する（下記R2）か、`--with-api` 時のみ実LLMで再判定
  - `_PendingInterventions` + `FacilitationController.arbitrate` を**本物のクラスで**実行（複製実装を作らない。これが v2 の核）
  - 沈黙は「次レコードの ms − 前レコードの end_ms」から算出。エコー窓・partner はリプレイでは常に非活性（対面ログにはAI音声レコードが無いため）。AI発話時間は「採択された介入の推定発話秒数（文字数/6.0）」で仮想クロック上に挿入し、その間の後続発話で割り込み（リトライ経路）も模擬する
- 出力: 各仮想 tick の採否（採択/抑制コード/hold）を intervention_review.jsonl 互換形式で吐き、既存の replay UI に「この turns.jsonl なら liveはここで喋っていた」を時系列表示する

### R2 記録済み判定の再生（no-api での意味論）

- live 実行時の interventions.jsonl / triage 注釈（turns.jsonl の record に保存済み）には、drift判定・fact判定・triage分類の結果が残っている。`--no-api` では**これらを候補投入イベントとして再生**する（同一入力に対する判定は既知なので再LLM不要）
- 記録が無い turns（古い形式）では、その checker はスキップし「判定記録なし」と明示（黙って0件にしない）

### R3 ポリシー差し替え口

- `--policy-override '{"af_l1": {"pause": 2.0}, ...}'`（JSON）で `_KIND_POLICY` の値を上書きして arbitrate を回せるようにする。閾値のA/B比較（同一ログ・別ポリシーの採否差分表）が1コマンドで出るのがゴール:
  `das replay <turns> --arbitrate --no-api --compare-policy a.json b.json` → 「Aでは発話/Bでは抑制」の差分一覧
- Controller 側は既にポリシー表駆動なので、コンストラクタに policy dict を注入できるようにする小改修のみ（グローバル定数の書き換えはしない）

### R4 既存モードの整理

- 既存の checker 単体検証モードは残すが、live と異なる駆動周期（`% INTERVAL`）を live と同じ条件（cursor 差分・時間間隔）に揃えるのは**やらない**（v2 の採否モードがその役割を吸収する）。docstring に「候補生成の質の検証用。タイミングは v2 を使え」と役割を明記

## テスト

- 固定 turns フィクスチャで: pause 不足で hold → 間が空いた turn で発火、cooldown 中の同種抑制、TTL 失効、の3シナリオが live の Controller テストと同じ結果になる
- policy override で pause を変えると採否が変わる差分テスト
- 記録済み drift 判定の再生が実LLMを呼ばない（monkeypatch で保証）
- AI発話挿入中の後続発話でリトライ経路に入る

## 受け入れ基準

16:42 障害セッション（`transcripts/2026-07-02_1642.turns.jsonl`）を `--arbitrate --no-api` で流し、実際の interventions.jsonl の trigger 列（manual×3, silence×1）と採択列が一致すること。これが「liveを再現できている」の実証になる。
