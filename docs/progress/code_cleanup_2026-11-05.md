# 重複・不要コードと配置の整理（2026年11月5日）

## 今回の変更

### 1. 巨大なワーカーを役割で分割

`src/das/asr/live/_workers.py`（1,904行）を削除し、`workers/` の次の実装へ分けた。

|モジュール|責務|
|`checks.py`|議題・論点・脱線・事実・参加・構造化の判定|
|`triage.py`|発話分類、呼びかけ、応答済みの確認|
|`af.py`|議論グラフによる提示とゲート|
|`agent.py`|進行役の介入制御|
|`voice.py`|音声接続・イベント・相手役切替|
|`lifecycle.py`|標準入力と終了|
|`common.py`|例外後のワーカー再開|

31個の関数・クラスすべてが移動先に存在することを構文木で照合した。呼び出し元とテストは所有モジュールへ直接接続し、旧パスへの転送モジュールは作っていない。最大のモジュールは656行。提示条件・回数・時間の値や、音声・話者帰属の校正値は変更していない。

### 2. 同じ処理の実装を統合

- 会話ログのJSONL読込み：CLI2か所、再採点、統合テストの4実装を、`das.transcripts.load_transcript` に統合した。空行の扱いとUtteranceの検証を維持した。
- TTSのPCM変換：シミュレーターとWAV生成の線形変換2か所を `das.audio.pcm.tts_pcm24_to_16` へ統合した。
- TTSのWAV変換：討論・重複発話の検査音声作成2か所を `tts_wav_to_pcm16` へ統合した。
- 元の線形・最近傍の補間方式は区別し、以前の標本値とバイト列が一致することを人工音声で確かめた。外部TTSへの要求や例外の扱いは各呼び出し元に残した。

### 3. 不要な入口・状態を削除

- `das.study.probe` の転送専用モジュール：接続確認は `das.study.bounded_probe` に一本化。
- `tests.test_facilitation_harness` の転送専用モジュール：手動実験は `scripts/check_facilitation.py` に一本化。
- `bounded_probe.reserve_call`：本体で使っていない転送関数を削除し、検査もProbeUsageを直接使う。
- 読取りも文字列による参照も見つからない内部状態7個：`_interrupted`、`_playback_status_warned`、`_played_bytes`、`_session_id`、`_last_input_at`、`_bias_threshold`、`_max_info_items`。関連する初期化・更新・型注釈を削除。
- `FacilitationAgent` の旧 `bias_threshold` 引数：説明に既に「使わない」と書かれ、リポジトリ内の呼出し元もなかったため削除した。この引数を外部コードで渡していた場合は修正が必要。

現在使う `das study`、従来の `das listen-soniox`、使用量制限付きの接続確認は維持する。古い転送専用のPythonモジュール名は、今回の整理で廃止した。

変更したPythonファイルのruff、差分の空白検査は通過。旧ワーカーへのコード上のimportは残っていない。関数本体の構文木を比較した検査では、8行以上の完全一致する重複グループは0件だった。この検査は、意味的な重複や不要な処理がすべて消えたことを保証しない。

実API・録音・音声再生は実行していない。本人の接続確認は失敗1回・残り2回の記録を保っている。API認証の401は今回の整理では解決していない。

## 削除しなかったもの

参照文字列だけで未使用を断定していない。CLIのデコレーター、HTTPの登録メソッド、音声イベント、getattrによる呼出しは、通常の関数参照とは別に確認した。

従来の議論グラフやWhisper系の処理は、既存コマンドから起動する経路があり、現役の別機能であるため一括で削除していない。話者帰属・エコー除去の変換は、今回統合したTTS検査音声とは入出力・補間の条件が異なる。過去の研究記録や再現用資料も保存した。

巨大な共有状態の内部など、なお整理余地は残る。今回は確認できた重複・参照のない状態・転送だけの入口を除き、実際の呼出しと検査に基づいて常駐処理の構成を変更した。
