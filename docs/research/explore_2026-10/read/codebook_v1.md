# 探索的コーディングの分類 v1（2026-10-18）

## 作り方

- GAP01（3人、生存課題の順位付け）と ES2003c（4人、リモコン設計の概念設計回）を、後続も含めて全文読んだ。そのうえで、観察から分類を作った。
- 比較不足や未検討情報の放置は、最初から分類項目にはしていない。
- 旧事前検証の候補・判定は参照していない（旧ログは監査でだけ読んだ）。
- この分類は探索用で、後続の発話を知ったうえで付ける。未来の発言を見ないオンライン検出の評価ではない。

## 単位

1. **区間（segment）:**
   - 一つの選択事項、または一つの局面を扱う、連続したターンのまとまり。
   - 会議の全ターンを、どれか一つの区間に入れる（困難がない区間も含める）。
   - 局面の種類:
     - 開示（各自の案や順位を言う）
     - 検討（理由を出し合う、比べる）
     - 決定（決め方の提案と受け入れ）
     - 発表（準備した内容の説明）
     - 進行（順序・時間・次の議題）
     - 確認（読み上げ・まとめ）
     - 雑談・その他
   - 一つの区間に複数の局面があれば、すべて書く。
2. **事例（case）:** 区間の中の、観察に値する出来事。困難らしい場面だけでなく、次も事例として残す。
   - 人が自力で解消した場面
   - 他者の働きかけで判断が進んだ場面
   - 停滞に見えて問題ではなかった場面
   - 再検討せずに決めることが合理的だった場面
   - 明確な困難が見つからない区間

## 行為の分類（参加者が選択を進めるためにしたこと）

| 記号 | 行為 | 観察の目安 |
|---|---|---|
| P1 | 自分の案・評価を出す | 「I put X as two」「I'd go for rubber」 |
| P2 | 理由・根拠を述べる | because、用途、経験、調査結果 |
| P3 | 理由や意味を尋ねる、説明を求める | 「Why flashlight」「could you draw it」「what did you have for fourteen」 |
| P4 | 異議・懸念を出す | 「You won't see that」「could be a weak point」 |
| P5 | 前提・状況・要件を持ち出す | 課題文の事実（80マイル）、想定（長くとどまる）、要件（予算、対象者） |
| P6 | 状態をまとめる、確認する | 読み上げ、「what's left」「we're set for fire」、決まったことの要約 |
| P7 | 進め方を決める・変える | 「work from back forward」、順番、時間の注意 |
| P8 | 決め方を提案する | 多数、譲る、相手に委ねる（「it was your two」「if you both put compass」） |
| P9 | 案を組み合わせる、新しい案を出す | 「incorporate it into the menu」、両方を満たす案 |

## 困難の分類（進行を難しくしていたと読めるもの）

すべて解釈である。内面は推定として書く。

| 記号 | 困難 | 観察の目安 | 注意 |
|---|---|---|---|
| K1 | 判断の前提・想定がそろわない、または明示されないまま決まる | 「とどまるか歩くか」「誰が使うか」が人により違うのに、そのまま順位や部品が決まる | 前提をそろえずに決めることが課題上問題でない場合もある |
| K2 | 判断に要る情報が分からない | 費用、用途、品目の正体、読み方が分からないと言う | 分からないまま決めるのが合理的なこともある（後で調べる、重要度が低い） |
| K3 | 出た理由や懸念が検討されないまま流れる、退けられる | 理由への応答がなく次へ進む、一言で退けられる | 「返答なし＝理解していない」とはしない。合意の黙認かもしれない |
| K4 | 何が決まったか・何が残っているかの把握が揺れる | 読み上げで食い違い、まとめに議論していない内容が入る、残りの確認 | |
| K5 | 決め手がなく、譲歩・委任・恣意で決まる | 「doesn't matter」「indifferent」 | 重要度の低い事項なら合理的。困難と断定しない |
| K6 | 時間・進行の圧力で検討が打ち切られる | 時間の注意の直後に決定・移行 | |
| K7 | 発言の重みに偏りがある（一人の主張が通りやすい、ある人の理由が採られにくい） | 特定の人の異議だけで決まる、ある人の自信のない言い方が続き採られない | 強い推定を含む。短い発言を不参加とはしない |

困難が見つからない区間は K0 とする。

## 事例ごとに残すこと

- 議論 ID、ターン範囲、時刻（元データ）、元の発話 ID（スクリプトで付与）
- 選択事項と、前後の文脈（短い要約）
- 観測できる発言・行為（原文の短い引用とターン番号）
- 種類: 困難／有用な行為／人が自力で解消／他者の働きかけで前進／停滞に見えて問題なし／再検討せず合理的／困難なし区間
- 行為・困難の記号
- 困難または有用と解釈した理由
- 別の解釈
- 後続の展開（何ターン後に何が起きたか）
- 外部支援: 役立ちそう／不要／判断不能。役立ちそうな場合は、何を（どの行為を）支えるかを書く
- その判断の不確実性: 高・中・低

## 判定上の注意

- 「返答なし＝理解していない」「短い発言＝不参加」「反復＝無駄」とは判定しない。
- 正解のある課題（GAP の生存課題には専門家の順位がある）でも、専門家の順位と違うことを困難の根拠にしない。課題上の前提を扱ったかどうかだけを見る。
- 内面（自信、遠慮、納得）は、推定であることを明記する。
