# ゼミ仲間の録音（2026-06-25 としや・わっち・黒田ほか）で事前登録の効果を測る手順

対面の実験と同じ状況——**議論の前に各自の声を登録し、本番の議論を流す**——を、
手元にある実際の対面の録音で再現して、登録なし／登録ありの話者同定の精度を比べる。
千葉コーパス（`enroll_eval_2026-09-28.md`）は録音環境が整った雑談だが、こちらは
1 本のマイクで録った実際の場で、関西弁の被り・相槌・笑いが多い。実環境の下限に近い。

所要時間の目安は約 25 分（登録 5 分＋実走 10 分＋正解付け 10 分）。

## 1. 使う録音

2026-06-25 の 15:54〜16:40 に収録した、松井・としや・わっち・ペンタて・黒田らの会話。
当時のシステムが付けたラベル（実名は当時手で付けたもの）から、内容は次のとおり。

| セッション | 長さ | 当時のラベルと発話量 | 備考 |
|---|---|---|---|
| 2026-06-25_1554 | 6.3 分 | 松井 76 s、としや 58 s、話者1 54 s、わっち 38 s、話者2 36 s、ペンタて 21 s | pyannote 試験（7/9）の対象 |
| **2026-06-25_1614** | **26.0 分** | としや 296 s、人物6 231 s、黒田 172 s、わっち 148 s、人物4 149 s、話者2 119 s | 同上。先頭 10 分で 291 発話 |

本番に流すのは **1614 の先頭 10 分**（人が多く、長い）。声の登録は **1554（別セッション）**から
作り、1614 にしか出ない黒田だけは **1614 の 10 分以降**から作る（採点する範囲と重ねない）。

| 登録する人 | 登録音声の出どころ |
|---|---|
| としや | 1554 の「としや」の発話 |
| わっち | 1554 の「わっち」の発話 |
| 松井 | 1554 の「松井」の発話 |
| ペンタて | 1554 の「ペンタて」の発話（21 s しか無い。足りなければ「話者1」がペンタてかを聞いて足す） |
| 黒田 | 1614 の「黒田」の発話、600 秒以降 |

**注意（大事）**: 当時のこのセッションの名前付けはかなり間違っている
（`docs/design/pyannote_live1_trial_2026-07-09.md` §8: 裁定でわっちと確定した 9 件のうち
現行ラベルは 4 件だけ、他は としや／人物6／話者2 に散っていた）。ラベルで区間を選ぶ
登録音声には他人の声が混ざり得る。作ったクリップは `data/voices/<名前>.wav` に残すので、
**登録前に必ず聞く**（1 人 60 秒。知っている声なのですぐ分かる）。混ざっていたら、
その人が一人で話している時間を `--add 名前=transcripts/2026-06-25_1554.wav@開始-終了`
で直接指定する（秒。複数回指定可）。

## 2. 手順

前提: `_incoming/enroll_docs.mbox` `_incoming/live_prep.mbox` `_incoming/zemi_eval.mbox` を
`git am` 済み（`eval/run_pair.py` と `enroll_voices.py --from-session` が要る）。

### 2.1 声の登録（クリップを聞く時間込みで 5 分）

```
uv run python scripts/enroll_voices.py --voices data/voices_zemi.json --seconds 60 \
  --from-session としや=2026-06-25_1554/としや \
  --from-session わっち=2026-06-25_1554/わっち \
  --from-session 松井=2026-06-25_1554/松井 \
  --from-session ペンタて=2026-06-25_1554/ペンタて \
  --from-session 黒田=2026-06-25_1614/黒田@600-
```

`# としや: 登録  2026-06-25_1554 の「としや」 発話 60.0s（0〜xxx 秒の範囲）→ data/voices/としや.wav`
のように出る。`data/voices/*.wav` を聞いて、他人の声が目立つ人は上の `--add` で作り直す
（`--voices` を同じにして `--add` だけ渡せば、その人だけ上書きされる）。
最後に `uv run python scripts/preflight.py --voices data/voices_zemi.json --expect としや,わっち,松井,ペンタて,黒田`。

### 2.2 実走（10 分。登録なし・登録ありを同時に流す）

```
uv run python eval/run_pair.py --wav transcripts/2026-06-25_1614.wav --name zemi1614 \
  --voices data/voices_zemi.json --max-speakers 5 --minutes 10
```

`--max-speakers` はその場にいた人数（5 人でなければ直す）。
`transcripts/zemi1614_none.*` と `transcripts/zemi1614_enroll.*` ができる。
ログは `data/pairs/logs/zemi1614_{none,enroll}.log`。
失敗したら（接続エラーなど）`--name zemi1614b` のように名前を変えて再実行する。

### 2.3 正解付け（10 分程度）

```
uv run python eval/annotate.py zemi1614_none
```

ブラウザが開く。区間ごとに音が鳴るので、話者の番号（1〜9）を押す。同じ人は同じ番号。
誰か分からなければ 0、複数人が重なっていれば M。保存は自動（`eval/gt_zemi1614_none.json`）。
番号と人の対応（例: 1=としや, 2=わっち …）はメモしておく。
291 区間あるが相槌は 1 秒程度なので、続けて押していけば 10 分ほど。

### 2.4 採点

```
uv run python eval/enroll_breakdown.py --gt eval/gt_zemi1614_none.json \
  --none zemi1614_none --enroll zemi1614_enroll --minutes 10
```

経過時間帯ごとに 正解／誤り／未確定 の文字数割合（相槌除く）が出る。
`transcripts/zemi1614_enroll.md` を開いて、登録した名前が最初の 1 分から出ているかも見る。

結果の表・両方の `.md`・`data/pairs/logs/*.log`・番号と人の対応を渡してもらえれば、
こちらで誤りの内訳（誰と誰を取り違えたか）を `eval/diagnose_live_session.py` で見る。

## 3. 見るところ

- 0〜1 分の正解率。登録なしは声が溜まるまで名前が付かない（千葉では 70.6%）。
  登録ありでここが高ければ、対面の実験でも序盤から名前が使える。
- 誤りの中身。登録した人同士の取り違えか、被りや短い発話か。
- 登録音声の出どころが別セッション（同じ場・同じマイク）でも照合できるか。
  対面の実験では議論の直前に同じマイクで録るので、これより条件は良い。
- 千葉（97.7%）と比べてどれだけ落ちるか。ここが実環境での実用精度の見積もりになる。

## 付録: 伊藤研ゼミの録音（同日 14:00〜15:41）でも同じことができる

`transcripts/2026-06-25_1400`〜`1520` は同じ日の伊藤研ゼミ（内田・山下・宮本・川瀬・岡田の
発表と質疑。伊藤先生・ありさか先生・丁先生が複数セッションに出る）。
本番 1509（川瀬の質疑、11.3 分、5 人前後）、登録は 伊藤先生=140652、ありさか先生・丁先生=1400、
川瀬=1506 の「人物1」から、という組み合わせで同じ手順が使える（`--max-speakers 5`、`--minutes` なし）。
発表形式なので、一人が長く話す場面での挙動を見たいときに。
