## 0. 設計上の前提と一つの重要な論点

`research_masterplan_2026-07-07.md` および `research_review_2026-07-07.md` は本実験を
「3-4名×3グループ×3条件ラテン方格・60分」と要約している。しかし hidden profile 課題を
3条件（3トピック）分実施し、かつ各条件後に短時間でもマニピュレーションチェック・簡易アンケートを
挟む設計にすると、**60分では物理的に収まらない**（個別ブリーフの黙読・議論・条件後アンケートを
3セット行うだけで最低90分規模になる）。

そのため本パッケージでは以下の2案を用意する。

- **標準版（推奨・約105分）**: §1-1 に記載。研究として最も安全（議論時間を削らない）。
- **短縮版（約70分、時間確保が困難な場合の代替）**: §1-4 に記載。議論時間を12分に短縮し、
  条件後アンケートを最小化する。この場合 hidden profile 特有の情報プーリング不全が
  観察されにくくなるリスクがあるため、**主結果として使う場合は考察で明記すべき限界**とする。

どちらを採用するかは参加者の拘束可能時間との兼ね合いであり、**[要確認: 参加者との事前調整で
決定]**。以下は標準版（105分）を基本形として記述する。

### 1-2. 条件割付表テンプレ（3グループ×3条件×3トピックの完全カウンターバランス）

Hidden profile の学習効果（構造化に慣れる効果）と、トピック固有の効果を分離するため、
**条件の順序**と**トピックの順序**を独立にラテン方格で統制し、かつ「どのトピックがどの条件で
提示されるか」もグループ間で入れ替える（Graeco-Latin方格、3×3では数学的に構成可能）。

条件: N = none（支援なし） / F = flat_rag（類似度提示のみ） / P = full_proposal（提案手法）
トピック: T1 / T2 / T3（`[教材確定待ち]`、`stage_c_materials_design_2026-07.md` §1-2 で確定予定）

| グループ | 1番目 | 2番目 | 3番目 |
|---|---|---|---|
| G1 | T1 × N | T2 × F | T3 × P |
| G2 | T3 × F | T1 × P | T2 × N |
| G3 | T2 × P | T3 × N | T1 × F |

検算（実験者向けメモ、割付ミス防止用）:
- 各条件は各順序位置（1番目/2番目/3番目）にちょうど1回ずつ出現する（N: G1-1番目, G2-3番目, G3-2番目）
- 各トピックも各順序位置にちょうど1回ずつ出現する
- 9通りの (トピック, 条件) 組み合わせが全てグループ間で異なり重複しない（Tn×条件の交絡を排除）

### 1-4. トラブル時の対応

| 状況 | 対応 |
|---|---|
| 録音機材が途中で停止した | バックアップ機材が動作していることを即確認。両方止まった場合は議論を一時中断し、参加者に謝罪の上、可能なら該当区間を実験者メモ（発言者・要旨）で補完し、データとして「録音不備あり」を明記して残す。実験自体は継続してよい |
| システム（flat_rag/full_proposal）が提示を行わない/エラーで停止した | 1回のリトライで復旧しなければ、その条件を「システム不調のため中断」と記録し、none相当の議論として継続するか、当日は中止し別日程で振り替えるかを実験者が判断（振り替え不可なら中断データとして質的分析からは除外し、量的集計にも含めない） |
| 参加者が途中離席・体調不良を訴えた | 直ちに議論を中断し、体調確認を最優先。続行可能なら再開、困難なら実験中止。同意書に基づき「いつでも中断できる」ことを再確認し、無理に継続させない |
| 議論が時間内に結論に至らない（15分で意思決定が終わらない） | あらかじめ「残り2分」「残り30秒」のタイムキープ合図を実験者が出す。時間切れの場合は「時間内での暫定結論」を聞き取り記録し、次条件へ進む。結論未到達自体もデータ（H3の記述に使える） |
| 参加者間で険悪な空気・強い対立が生じた | 議論自体は課題の一部として許容するが、人格攻撃・ハラスメントに発展する兆候があれば実験者が「一旦休憩を挟みましょう」と介入し中断。深刻な場合は実験中止し個別にケア |
| 参加者が研究目的（何を測っているか）を議論中に勘づいた発言をした | 議論は止めない。デブリーフィング時にその発言を踏まえて追加説明し、データにその旨を注記（結果解釈時に除外を検討する候補として記録） |
| 条件の割付を実験者が誤って入れ替えてしまった | 気づいた時点で中断せず最後まで実施し、実際に行った順序・条件を正確に記録する。分析時に割付表テンプレの記録値を正とし、当初の計画表とは別に「実施記録」を残す |
| グループの人数が当日欠席で3名未満になった | 3-4名を hidden profile の下限としているため、2名以下では情報分散の設計が崩れる。原則実施を見送り別日程に振り替える。やむを得ず実施する場合は「補完データ（案2相当の観察扱い）」として量的集計から除外し記録のみ残す |

## 4. 事後インタビューガイド（半構造化・10分）

目的: アンケートでは拾いきれない「介入が役立った/邪魔だった瞬間」の具体的な文脈を掘り、
質的ケース記述（`research_review_2026-07-07.md` §5案1の分析方針で必須とされる要素）の
素材を得る。個別インタビューを推奨（他の参加者の前だと言いにくい評価が出る可能性があるため）。
時間が確保できない場合はグループ合同で実施してよいが、その場合は発言者を明示して記録する。

**進め方の原則**:
- アンケートの自由記述（E1・E2）に既に具体的な場面が書かれていれば、そこから深掘りを始める
（回答用紙を手元に置いて参照する）
- 「なぜ」「具体的にはどんな」で掘り下げ、抽象的な感想で終わらせない
- 3条件を比較させる質問は、参加者が条件名を覚えていない前提で「1回目・2回目・3回目」
「画面に情報が出てきた回・出てこなかった回」等、参加者が認識しやすい言い方に言い換える

### 質問系列

```
導入（1分）
Q0. 3回の話し合い全体を振り返って、率直にどうでしたか（自由に話してもらう、
　誘導しない）。

介入が役立った瞬間を掘る（3分）
Q1. 話し合いの中で、画面に何か情報が表示されて「あ、それは気づかなかった」
　「それは使える」と思った瞬間はありましたか。
　→ あれば: それはどんな場面でしたか。その情報を見て、実際に発言や考えが
　　変わりましたか。
　→ なければ: そもそも画面の情報にどのくらい注意を払っていましたか。

介入が邪魔だった瞬間を掘る（3分）
Q2. 逆に、画面の情報やタイミングが「今はいらない」「話の腰を折られた」と
　感じた瞬間はありましたか。
　→ あれば: それはどんな場面でしたか。何がその情報を「邪魔」だと
　　感じさせましたか（タイミング・内容・言い方など）。
　→ なければ: 情報が出てくること自体に慣れた/気にならなかった、という
　　理解でよいか確認。

未共有情報・反論の扱いを掘る（2分）
Q3.（該当する場面があれば）自分だけが知っていた情報を話し合いの中で
　出しそびれた、あるいは逆に出せた、という経験はありましたか。
　→ 出せた場合: 何がきっかけで出す気になりましたか。
　→ 出しそびれた場合: 何が出しにくくしていましたか。

Q4. 自分の意見に対する反論を受けて、その場で反論し返せなかった、あるいは
　後から「ああ言えばよかった」と思った場面はありましたか。画面の情報が
　その状況にどう関わっていましたか（関わっていなくても可）。

締め（1分）
Q5. もし今回のようなシステムが実際の会議で使われるとしたら、どんな場面で
　使ってほしい、あるいは使ってほしくないと思いますか。
```

**記録方法**: 逐語録が理想だが時間的制約がある場合は要点メモ＋タイムスタンプ（該当する
発言があれば録音の該当箇所を後で参照できるように）。インタビュー内容はコーディング
（`research_masterplan_2026-07-07.md` 12月工程「補足分析・インタビューコーディング」）
の一次データとして扱う。

## 5. 分析上の注意（実験者向けメモ）

- 小標本（n=9〜12）のため、群間の有意差検定を結論の根拠にしない
（`research_review_2026-07-07.md` §5・§6 の統計方針を踏襲）。効果量・区間推定・
方向の一貫性・質的ケース記述を組み合わせる。
- Q1/Q2（マニピュレーションチェック）の結果は、教材が意図通り機能したか
（none条件でデコイ選択肢に流れやすいか）の確認に必須。ここが機能していない
グループのデータは、質的分析からは除外せず「教材が効かなかった事例」として
別途記述する。
- 介入ログの手続き/内容分類（§3-D）は実験終了後、録音・システムログを突き合わせて
実験者が行う。参加者に「これは手続き介入でした」と当日伝える必要はない
（アンケートは介入の「内容カテゴリ」を参加者に見せた上での評価ではなく、
実際に体験した介入全体への印象を聞く設計にしてある）。
