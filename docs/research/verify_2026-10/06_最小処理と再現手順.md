# 最小処理と再現手順

## 最小処理（`scripts/minimal_pipeline.py`）

- **入力:** その時点までの話者付き履歴（`ターンID|開始秒|話者|発話`）
- **出力:** 次の3つ
  - 証拠付きの理由と前提の対応
  - 支援する／控える／判断不能
  - 3種類の提示文

### LLM と固定ルールの分担

| 部分 | 担当 | 内容 |
|---|---|---|
| 履歴の切り出し | 固定ルール | 判定時点より後の発話を入れない（`cut`） |
| 理由の抽出、前提の推定（種類 T1〜T6、証拠水準 E1〜E3）、明示済み・両立済み・発表中の判定、提案手法の文面 | LLM | 今回は API を直接呼べないため、判定用の入力（`prompt`）を Claude のサブエージェントに渡し、出力 JSON を受け取った |
| 形式の検査、引用の実在と発言 ID の検査、時点より後の参照の検査 | 固定ルール | `gate` と `scripts/check_outputs.py` |
| 支援判定のゲート | 固定ルール | 次をすべて満たすときだけ「支援する」を残す。それ以外は控える・判断不能に落とす |
| 3種類の提示文と長さの検査 | 固定ルール | 静的案内は固定文。引用のみは証拠引用から作る。提案手法は LLM の文面で、200字を超えると警告する（200字は今回の運用上の目安で、先行研究の値ではない） |

ゲートの条件:

- 主分析の対（E1/E2、T1/T2）がある
- 証拠の話者が2人以上
- 引用が実在する
- 未明示
- 両立済みでない
- 発表中でない

### 実データでの動作確認

- 84時点の出力にゲートを当て直した（`batch`）。LLM の判定とゲート後の判定は、84件すべてで一致した（支援2、控える82）。
- 支援2件は、どちらも提示文が長すぎる警告になった（313字、394字）。
- **ゲートで検出できない失敗:** 評価を想定として扱う（F1）、可能を必要に変える（F2）、対立しない理由を対にする（F3）。これらは意味の判断なので、固定ルールでは検出できなかった。事後評価者が見つけたもので、現時点で自動の検査はない。

### 話者情報・音声・実時間性が何に必要か

- **話者情報:** 異なる話者の理由を対にすることと、発言を話者に帰属させることに必須。話者の取り違えは、そのまま帰属の誤り（B4 の違反）になる。
- **音声:** 対面で全員に同時に届ける手段の候補。ログの検証には不要。今回の提案手法の文（313〜394字）は、音声で一度に聞く量を超えていた。
- **実時間性:** 判定時点で履歴を切り出せれば足りる。120秒ごとの判定なら、数秒の遅延は問題にならない。

### 未検証のこと

今回の性能は、公開転記（人手の書き起こし、正しい話者）でのもの。実時間の音声認識と話者同定を通した性能は検証していない。

## 再現手順

元データは同梱しない。取得先は `03_データ選定記録と利用条件.md`。

1. **前処理と、検証用の選定・切り出し・暗号化:**
   ```
   python3 -I scripts/select_and_seal.py <precheck_root> <deli_dir> sealed
   ```
   - `<precheck_root>/raw` に GAP・AMI を置く。`prep.py` は旧作業のものを使う。
   - 合言葉はスクリプトが無作為に作るので、再実行すると合言葉と暗号文は変わる。選定と時点の切り方は同じになる。
2. **時点判定:** `prompts/judge_timepoint.md` を判定者に渡し、k 番目の時点だけを担当させる。出力は `timepoint/` に置く。
3. **固定処理の検査:**
   ```
   python3 -I scripts/check_outputs.py <verify_root>
   ```
4. **対の重複のまとめ:**
   ```
   python3 -I scripts/dedupe_pairs.py <verify_root>
   ```
5. **比較用の3種類の提示文:**
   ```
   python3 -I scripts/make_variants.py <verify_root>
   ```
6. **事後評価:** `prompts/audit_posthoc.md` を、2人の評価者に独立に渡す。出力は `audit/` に置く。
7. **集計:**
   ```
   python3 -I scripts/aggregate_audit.py <verify_root>
   python3 -I scripts/summarize_results.py <verify_root>
   python3 -I scripts/minimal_pipeline.py batch <verify_root>
   ```

LLM の判定は確率的で、同じ入力でも出力は変わりうる。今回の判定結果そのものは `timepoint/` と `audit/` に保存してある。
