# 検証計画と固定基準 v1

- 固定日時: 2026-10-19（UTC）。ハッシュは `02_検証計画と固定基準_v1.sha256` に記録する。
- 検証用データの中身を読む前に固定した。固定後に変えた点は、末尾の「変更記録」に、変更前の版を残して書く。変更後の結果は、確認的検証の結果と混ぜない。

## 1. 検証する案（固定）

参加者が述べた異なる理由について、それぞれが依存する前提を根拠発言とともに明示し、参加者が前提の違いを判断に取り込むことを支援する。

- 前提の統一や合意は強制しない。条件付きの判断、複数の想定への対応、違いを残した選択も認める。
- 一般的な比較支援、未確認情報の補充、決定記録支援には置き換えない。

想定する仕組み（段階ごとに別々に判定する）:

1. 前提の違いを明示する
2. 人が各理由の適用条件を検討する
3. 条件を踏まえて、理由を採用・反駁・限定・留保する
4. 選択判断に接続する

ログでは、段階1 で示す内容の妥当性と、段階2〜4 が自然な会話の中で起きたかだけを見る。支援によって段階2〜4 が起きるかは、人による試行でしか確かめられない。

## 2. 用語と分類（第1段階で決めたもの）

**前提の種類:**

- T1: 事実認識
- T2: 行動方針・利用状況などの想定
- T3: 評価基準・価値の優先順位
- T4: 単なる選好
- T5: AI の解釈が要るもの
- T6: 複数の想定の両立

T3・T4 は前提として扱わない。T6 は「既に扱われた」として控える。

**証拠水準:**

- E1: 明示
- E2: 強い示唆（理由の内容から前提が一つに決まる）
- E3: 推測

**前提差の対（分類単位）:** 次をすべて満たす2つの理由。

1. 異なる話者の理由である。
2. 同じ選択事項（または全体の順位付けの基準）について、推す選択肢・順位・採否が違う。
3. それぞれの理由の強さが、ある前提（T1 か T2）に依存する。
4. 2つの前提が違い、片方の前提の下では、もう片方の理由の強さが変わる。
   - 「理由が違う」だけ、「前提が違う」だけでは対にしない。
   - 前提が違っても、両方の想定で同じ選択肢が支持されるものは対立ではない。例: 寒さは、とどまる場合も歩く場合も衣類を支持する。

**主分析:** 対の両方の前提が E1 か E2 のもの。E3 を含む対は、推測依存の分析として別に数える。

## 3. 時点ごとの判定（オンライン相当）

### 判定時点（固定）

| データ | 判定時点の決め方 | その時点の履歴 |
|---|---|---|
| 音声の書き起こし（GAP、AMI） | 経過120秒ごと（120, 240, 360, ... 秒）。最後のターンの開始時刻を超える時点は作らない | 終了時刻が判定時点以前のターンだけ |
| 文字チャット（DeliData） | 発言（message_type が MESSAGE のもの）10件ごと | その10件目までの発言と、それ以前の提出（SUBMIT） |

- 実際の終了時刻など、未来の情報は時点の決め方に使わない。
  - 音声: 最後のターンの開始時刻は「その時点で会話が続いていたか」の判定にだけ使い、履歴には入れない。
  - チャット: 最後の発言数は使わない。10件ごとの時点が最後の発言を超えたら作らない。
- 120秒は、20分の議論で約10回の判定機会になる間隔として、運用上決めた値（先行研究の値ではない）。

### 判定者に渡すもの

- 呼び出し側（主作業者のスクリプト）が切り出した、その時点までの履歴だけを渡す。
- 履歴ファイルは時点ごとに別の合言葉で暗号化する。判定者には、担当する時点の合言葉だけを渡す。
- 元データ（zip、前処理済みの全文）は、判定が終わるまで暗号化して置く。合言葉は主作業者だけが持つ。
- 一人の判定者は、各議論の同じ番号の時点（例: すべての議論の3番目の時点）だけを担当する。同じ議論の、より後の時点を見ることはない。

### 判定者の出力（時点ごと、JSON）

- **対象となる理由:** 話者、推す選択肢、理由の要約、発言 ID、原文の引用
- **各理由が依存する前提:** 種類 T1〜T6、証拠水準 E1〜E3、証拠の発言 ID と引用
- **判定:** 支援する／控える／判断不能
  - 控える理由: 既に扱われた、両立済み、発表中、対がない、T3・T4 のみ、推測のみ、材料不足
- **提示文（提案手法）:** 2文以内。型は 4節。
- その時点で、参加者が既に前提の違いを言葉にしているか（はい／いいえ）

### 支援する条件

すべてを満たすとき、支援する。

1. 主分析の条件を満たす前提差の対が、その時点の履歴にある。
2. 参加者が、その対の前提の違いを、まだ言葉にしていない。明示の目安は次のいずれか（どれかが他の参加者に応答されていれば「扱われた」）。
   - 「〜なら」「〜の場合」と条件として述べる
   - 「AとBのどちらを想定するか」を問う
   - 違いを指摘する
3. 発表・説明の途中ではない。直近3ターンの発話の大半が一人の準備された説明で、他の参加者がまだ検討に入っていない状態を「途中」とする。
4. 参加者が、その対について両立の想定（T6）を既に述べていない。

### 控える条件

上の 2〜4 のいずれかに当たる、または対がない（推測しかない、T3・T4 しかない、理由が一人分しかない）とき。証拠を確かめきれないときは判断不能とする。

### 終了条件

- 同じ対について、参加者が前提の違いを言葉にした以後の時点では、その対を支援しない。
- 同じ対について、一度支援と判定した後の時点では、重複として扱う（下記）。

## 4. 提示文の型（3種類。比較のため同じ時点で作る）

1. **静的案内（固定文。会話に依存しない）:**
   > 理由によっては、どんな状況を想定しているかで重みが変わることがあります。それぞれの理由がどんな想定に立っているか、確かめてから決めても構いません。
2. **引用のみ:** 提案手法と同じ根拠発言を、話者付きで並べるだけ。前提の記述や問いは付けない。
   > 〇〇さん「（引用）」。●●さん「（引用）」。
3. **提案手法:** 話者、引用、前提を対応づけ、違いの扱いを問う。
   > 〇〇さんは「（引用）」と、□□の場合を想定して△△を挙げています。●●さんは「（引用）」と、■■の場合を想定して▲▲を挙げています。この違いを、選ぶときにどう扱いますか（どちらかを想定する、両方に備える、違いを残すなど）。

提案手法の文の規則:

- 前提は証拠発言に出ている言葉で書く。
- 新しい二択や評価軸を加えない。
- 発言の留保・否定・仮定（「たぶん」「〜なら」）を残す。
- 参加者の主張を事実として断定しない（「〜と言っています」の形）。

静的案内と引用のみは、判定者の出力から固定の処理で作る。引用のみは、提案手法の証拠引用から作る。

## 5. 評価項目

### A. 対象場面の存在

- 議論ごとに、主分析の対が1つ以上あるか。
  - 議論が独立の単位。時点や発言の数は独立の単位として扱わない。
- 課題（GAP、AMI、DeliData）ごとの分布。
- 対がない議論も数える。前提差はあるが判断に支障がない例も記録する（事後の全体分析）。

### B. 抽出・提示の妥当性（支援と判定した出力ごと。別の判定者と固定処理）

| # | 項目 | 方法 |
|---|---|---|
| B0 | 引用が、示した発言 ID の発言に実在する。その発言が判定時点以前のものである | 固定処理 |
| B1 | 前提が証拠発言に支えられている | 判定者 |
| B2 | 異なる条件を誤って対立扱いしていない | 判定者 |
| B3 | 価値観・選好を事実の誤りとして扱っていない | 判定者 |
| B4 | 参加者の主張を事実として断定していない | 判定者 |
| B5 | 新しい二択・評価軸を持ち込んでいない | 判定者 |
| B6 | 元の発言の留保・否定・仮定を保っている | 判定者 |

各項目は「満たす／満たさない／不確か」で評価する。合計点は出さない。

- **重大な誤り:** B0、B1、B2、B4 のどれかを満たさないもの。
- **重大な誤りなし:** B0〜B6 のすべてが「満たす」または「不確か」で、B0・B1・B2・B4 が「満たす」のもの。

### C. 支援の余地と不要介入（事後。後続を読んで評価する。介入の効果ではない）

- **C1:** 判定時点で、既に前提の違いが明示・扱われていたか（判定の見落とし）。
- **C2:** 発表・説明の途中だったか。
- **C3:** 判定時点の後、次の判定時点まで（最大120秒。チャットは次の10発言まで）に、人が自力で前提の違いを扱ったか。
- **C4:** 支援が置き換えそうな、人の有用な行為（理由を尋ねる、想定を述べる、両立させる）が、その時点の前後にあったか。
- **C5:** その対の前提差は、後の決定の理由に関わったか（関わった、関わらない、不明）。

「不要介入」は、C1、C2、C3 のどれかに当たるものとする。

### D. 比較（同じ時点の3種類の提示文）

次の5点を比べる。

- 内容の正確さ（B と同じ観点）
- 具体性（どの理由・選択肢・前提に答えればよいかが分かるか）
- 新しい情報の混入
- 追加される推論（前提の記述など、引用にない内容）
- 提示量（文字数）

ログから参加者への効果の順位は付けない。引用だけで対応が明確な例と、提案手法の追加価値がありそうな例を、両方残す。

## 6. 重複・分母

- **同じ対:** 同じ議論で、支援と判定した2つの出力の証拠発言 ID が1つでも重なれば、同じ対とする。対の数は、この規則でまとめた数。
- **分母の区別:**
  - 議論数（独立の単位）
  - 判定時点数
  - 支援出力数
  - 対の数
  - 割合を示すときは、必ず分母を書く。

## 7. 全体分析（事後）

時点ごとの出力を保存した後に、別の判定者が全文を読み、次を記録する。

- 前提に関わる場面
- 人が自力で扱った場面
- 扱われなかった場面

これは後続を利用した探索・事後分析で、その時点で検出できたこととは区別して報告する。

## 8. 検証データの選定規則（中身を見る前に固定）

| データ | 規則 | 選ばれる議論 |
|---|---|---|
| GAP | 3人、会議の長さ5分以上、旧作業で未使用（1、7、8、18、24 を除く）、グループ番号順に6件 | 9、16、19、20、21、22 |
| AMI | 部品を決める回（c）。旧作業で使っていない ES2005c と、別の収録地点の IS1000c、TS3003c。後二者は各収録地点の最初の番号 | ES2005c、IS1000c、TS3003c |
| DeliData | 3人、発言（MESSAGE）30件以上、会話 ID の辞書順に4件 | 選定スクリプトで決定 |

- 曝露の管理: ES2005c は旧作業で前処理だけ行い、発言内容は誰も読んでいない。GAP28 は前処理のみで、今回は使わない。
- 「未使用」は、今回と過去の判定への曝露についての管理で、モデルの学習データに含まれていないことの保証ではない。

## 9. 最終判断の基準（運用判断。先行研究の値ではない）

### 人による予備試行へ進む

次の3つをすべて満たすとき。

1. 主分析の対が、検証用の議論で3議論以上、かつ2種類以上の課題にある。
2. 支援出力のうち、重大な誤りのないものが過半数である。
3. 不要介入（C1〜C3）に当たる支援出力が、過半数ではない。

### 一度修正してから進む

1 は満たすが、2 か 3 のどちらかを満たさない。または、対が1種類の課題に偏る。

### 主研究として採用しない

次のいずれかに当たるとき。

- 主分析の対がある検証用の議論が2つ以下。
- 支援出力の過半数に重大な誤りがある。
- 支援出力の大半（3分の2以上）が不要介入に当たる。

## 10. 感度分析（あらかじめ決めておく）

1. 推測依存（E3）を含めた場合。
2. 「同じ対」の規則を、証拠の重なりではなく、選択事項が同じかどうかで決めた場合。
3. AMI を除いた場合と、DeliData を除いた場合。
4. 判定者と事後評価者の評価が分かれた項目を、保守側（満たさない）に倒した場合と、寛容側に倒した場合。
