# 研究設計: 段階C（対面実験）の hidden profile 型教材

対象: 実験教材の設計（作成作業はLLM併用で可能、対面実験そのものは秋）。根拠: `significance_2026-07.md`（推奨B・仮説H1〜H4）、`research_plan_2026-07.md`。これは実装設計書ではなく研究教材の仕様。

## 1. 課題形式

**隠されたプロファイル（Stasser & Titus 1985）の変形**: 最適解の根拠が参加者間に分散配置され、共有情報だけでは準最適解が選ばれるよう設計された意思決定課題。本研究では「事前文書（evidence源）」に未共有情報を仕込む点が古典と異なる——**AIが文書からevidenceを引き、関係ラベル付きで提示することで未共有情報が場に出るか**（仮説H1）を測る。

## 2. 教材の構成（1トピックあたり）

- **論題**: 政策/組織意思決定型で3〜4択（例: 既存資産の「生成AI講義許容」系 or 新規「部門横断ツール導入の選定」）。選択肢ごとに賛否材料が非対称になるよう設計
- **共有ブリーフ**: 全員が読む1ページ。共有情報のみで判断すると選択肢Xが最良に見えるよう構成（デコイ）
- **個別ブリーフ**: 参加者ごとに異なる1ページ。真の最良選択肢Yを支持する情報／Xを弱める情報を分散配置（各自は断片しか持たない）
- **事前文書（システム投入用）**: 個別ブリーフの内容を**含む**詳細資料。none/flat_rag/full_proposal の条件差は「この文書がどう参照されるか」に現れる。planted contradiction（既存資産 `data/docs_policy/contradiction_planted_evidence.md` の手法）も1件仕込み、fact/attack 提示の発火機会を保証する
- **正解基準**: 全情報を統合すれば Y が支配的になる採点表（実験後のマニピュレーションチェック用）

## 3. 測定との対応（significance の仮説へ）

| 仮説 | 教材側の仕掛け | 指標 |
|---|---|---|
| H1 未共有情報の表出 | 個別ブリーフ＋事前文書の対応表（情報ID付き） | 情報IDごとの言及検出（transcript照合）、citation_rate(source別) |
| H2 未応答反論の回収 | Xへの攻撃材料を文書側に配置 | pct_attacks_answered（観測用AF） |
| H3 記憶の外在化 | 情報量を意図的にWM容量超に（選択肢×属性で12+セル） | 重複主張率・忘却反論復活率 |
| H4 介入の受容 | — | キャンセル率・事後アンケート |

情報IDは文書・ブリーフの各文に振り、「どの情報が誰に配られたか」のマトリクスを機械可読（CSV）で保持する。**言及検出が自動化できることが教材の設計制約**（数値・固有名詞を含む一意な言い回しにする）。

## 4. 実験デザイン上の決定事項（ユーザーと要確認）

1. 被験者内 vs 被験者間: 計画書は被験者内（5-8名×60分）。hidden profile は学習効果が強いため、**トピックを条件数ぶん用意し、条件×トピックをラテン方格で回す**必要がある → 教材は最低3トピック（none/flat_rag/full_proposal）。4条件目（unlabeled）は対面では落とす判断もあり
2. 1グループの人数: 3〜4名（hidden profile の標準）×2〜3グループが現実的
3. アンケート: 主観5軸の人間向け翻訳＋NASA-TLX＋UEQ短縮版。judge.md の指標定義を人間用に書き直す（盲検化した中立表現をそのまま流用）

## 5. 作成手順（LLM併用・対面不要で進められる範囲）

1. トピック3件の骨子（選択肢・属性表・情報配置マトリクス）を設計 → ユーザーレビュー
2. LLMで文書・ブリーフを起草 → 情報IDの一意性チェック（自動: 文書間で文字列重複がないか）
3. シミュレーションでプレテスト: LLMペルソナに個別ブリーフを与えて3条件で回し、(a) デコイが効く（none で X が選ばれがち）(b) full_proposal で情報IDの言及が増える方向に出る、を確認してから人間に使う——**教材の妥当性検証がシミュで先にできる**のが本設計の利点
4. 倫理申請・同意書ドラフト（研究室のテンプレートに合わせる。9月中）
