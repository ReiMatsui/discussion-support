# 進捗報告スライド 改訂メモ（2026-10-21）

対象: `進捗報告_選択肢の記録と確認_2026-10.pptx`（旧版、20 枚）→ `進捗報告_選択肢の記録と確認_2026-10_v2.pptx`（新版、28 枚）。旧版は上書きしていない。

## 1. 主要な変更点と理由

| 変更 | 理由 |
| --- | --- |
| 表紙を「対面議論の決定を支援する音声エージェント／選択肢を外す・選ぶ発言の記録と確認」に変更 | 「閉じ方を預かる」などの比喩をやめ、何をするかを平易に書く |
| 「閉じ方を預かる」「決定の引き受け手」「拘束に進める」「決定連鎖の完結」を本文から削除 | 説明なしでは意味が分からない表現を使わない |
| 対象場面のスライドを新設（候補を絞って一つに決める段階、暫定） | 「比較する段階」「除外を提案する発言」「成立した発言」「発言なく消えた選択肢」を区別し、検出が扱えるのは観測できる発言だけと明記 |
| 課題を A（共有と判断）、B（外す発言のあとの応答）、C（対面音声で進行中に確認する意味）、課題例の 4 枚に分割 | 圧縮した言い切りをやめ、観測と仮説、特徴と設計判断を分ける |
| 「戻れるのは数秒だけ」「この数秒に介入できるのは音声主体だけ」「チャットなら問題が起きない」を削除 | 断定に根拠がない。対面であること自体を新規性にしない |
| エージェントの動作を「記録と読み返し、補足・訂正の記録、最終確認」に組み直し、「確定します」「一旦外して進めます」「保留」を廃止 | AI が決定を宣言しない設計に統一。無応答は記録を変えず監視へ戻る。異論は記録し、集団の方針は決めない |
| 発話例を「B を外す提案と、駅から遠いという理由を記録しました。補足や訂正があればどうぞ」に変更 | 記録したことと、参加者が決めることを分ける文言 |
| 「議長ではなく書記」「ペンを持った書記」の比喩を本文・図・発表者ノートから削除。提案の説明を「働きかける場面、読み返す内容と応答の機会、支えようとする行為、期待する変化（仮説）」の順に書き直した | 役割の比喩で提案を小さく限定せず、介入を直接説明する。効果は未検証なので仮説として示す |
| 「戻せるから誤分類しても問題ない」を削除し、誤った読み上げの誘導と訂正の負担を評価指標と逆効果に入れた | 指示どおり |
| システム構成、保持する状態、アルゴリズム 1・2 の 4 枚に分割。矢印にデータを付記、分岐に条件を付記、戻り経路を描いた | 箱を並べただけの図をやめる。参加者の状態とシステムの処理状態を別の表にした |
| LLM の担当を「抽出と応答の分類」、固定処理を「引用の実在確認、重複防止、時間管理、停止、記録更新条件、出力形式検査」と明記 | 「LLM は決定行為と理由の検出だけ」という不正確な説明をやめる |
| 数値（1.2 秒、6 秒、最大 2 回、60 秒、45 秒）を補足 A に移し「設計上の初期設定（未検証）」と明記。「20 分で 2〜4 回、合計 1 分」を本文から削除 | 実証結果のように読める書き方をやめる。架空例の発話数と秒数は列に合わせて数え直した（例 1: 2 回、約 10 秒） |
| 理由の引用の探索範囲を「直近の発言を優先し、同じ選択肢の記録にある過去の発言も対象」に変更 | 直近 20 秒だけで十分と仮定しない |
| 動作例を 2 枚に分け、例 1 は読み返し→補足→別の参加者の検討→判断の変更までの四段、例 2 は訂正、無応答、既出の理由の再利用 | 情報が足されただけで判断改善と呼ばない。反実仮想の断定（AI なしなら必ず消える）を削除 |
| 「しないこと」を「参加者とエージェントの役割」に統合し、制約ごとに理由と処理での扱いを付けた。目的・まとめからの重複を削除 | 否定形の分散をやめ、設計上の制約として動作に結び付ける |
| 近い研究との比較を本文に移し（記録・要約、議長の定式化、Revoicing、LLM 進行）、「新規性の整理」を 1 枚追加（技術・介入設計・実証知見・弱い部分） | 新規性は本文で扱う。「対面で音声介入した例がない」「内容を足さないから新しい」を新規性にしない |
| 研究目的を「読み返して確認の機会を設けると、参加者による理由の補足・訂正と、その後の判断がどう変わるかを調べる」に書き直し、RQ を参加者の行為と判断・負担に対応させた | 概念を知らなくても読める構成 |
| 主比較は「記録のみ（記録画面あり、無発話）vs 読み返しと確認」を維持し、選ばなかった比較（読み返しのみ vs 機会あり、エージェントなし）と理由を明記 | 条件を増やさない。追加効果の分離は次の研究に回す |
| 評価指標を「人の行為（主）」「負担と副作用」「補助（正答）」に分け、エージェントの発話は数えないと明記 | AI の読み上げで自動的に増える指標を避ける |
| 実験手順に、組数未確定、従属性、順序と持ち越し、評価者を伏せられない限界を明記 | 数字を確定値として書かない |
| 予備試行の確認事項を「検出」「意味の保持」「機会として受け取られるか」「検討につながるか」「追認圧力・中断」に変更。「2 本で消失 1 件以上」「うんが大半なら縮小」を削除 | 改善で直せることと、中核仮説の不支持を分ける |
| 実装状況を「実装済み／設計済み／未確認」で分けた | 実装済み機能を作り上げない |
| 節番号の不整合（実験計画のあとに実装）を直した | 指示どおり |

## 4. 研究者が最終判断すべき未確定事項

1. 対象場面を「候補を絞って一つに決める段階」に限定するか。暫定として資料に書いたが、確定ではない。
2. 参加者の「成立の発言」をどう定義して記録するか（他の参加者の明示的な同意、または進行役的な「じゃあ B は外しで」への同意）。これが記録画面の「除外成立」の根拠になる。
3. 最終確認で読み上げる対象（理由や異論の記録がある選択肢だけか、全選択肢か）。
4. 主比較を「記録のみ vs 読み返しと確認」で確定するか、「読み返しのみ vs 機会あり」に替えるか。資料は前者を維持し、理由を書いた。
5. 組数、人数、募集元。資料では未確定（目標 6 組以上）とした。
6. 初期設定値（1.2 秒、6 秒、最大 2 回、60 秒、45 秒）。予備試行で調整する前提で補足 A に置いた。
7. GPT-Live に定型文をそのまま読ませられるか。未確認。言い換えが起きるなら、読み上げ専用の音声合成に切り替える判断が要る。
8. 評価者に条件を伏せられない問題の扱い（エージェントの発話を除いた文字起こしでの符号化、または第三者による符号化）。
9. 記録画面を両条件で見せるか（資料では両条件で見せる前提）。見せない場合は主比較の意味が変わる。
10. 発表者ノートの確認度のうち、Mojzisch 2008 と Greitemeyer 2006 は作業論文版での確認。掲載版との頁・文言の照合が未了。
