# 設計書（バックログ）: 音声レベルAEC統合 — 自前PCMを参照信号に

**状態: 未発注**。着手トリガー: S2/S3 計測（`near_term_validation_plan_2026-07.md`）で「AI音声の混入率」または「AI発話と重なった人間発話の帰属正解率」が基準を割った場合のみ。割らなければ実施しない（現行のテキスト類似・声紋・再生区間の3層防御で足りているため）。

## 背景

AI音声のマイク回り込みは現在「認識後」に3層で除去している。原理的には、AI音声のPCMはシステム自身が生成しており（再生前から完全に既知）、エコーキャンセラ（AEC）の参照信号として理想的——通話アプリのAECと同じ引き算が、より有利な条件でできる。現状それをしていないのは、STT/声紋が生マイク音を前提にsounddevice(PortAudio)の生ストリームで取っており、OSの音声処理層（Voice Processing I/O）を通っていないため。

## 設計原則（既存システムを崩さないための拘束）

1. **完全 opt-in**: CLI `--aec`（既定OFF）。OFF時は既存経路に1バイトも変更を加えない並行実装
2. **二股構成**: AEC後の音声は **STT送信専用**。**声紋照合・声紋登録は従来どおり生音声**を使う（声紋閾値群は生音声の類似度分布でチューニング済みであり、AECの残差歪み・ダブルトーク時の抑圧が分布を崩すリスクを構造的に遮断する）
3. **AB計測可能**: 録音WAVは生音声・AEC後の両方を保存（`.wav` / `.aec.wav`）。効果検証は同一会議の両WAVを score_overlap_test / STT にかけて比較

## 実装方針

- ライブラリ: WebRTC Audio Processing（AEC3）系のPythonバインディング、またはspeexdsp。選定時に (a) 16kHz mono対応 (b) 参照信号の外部供給API (c) メンテ状況、を確認
- 参照信号: `agents/_base.py` の再生パス（`_audio_q` → 再生スレッド）が**実際にスピーカーへ書き込んだフレーム**を、書き込み時刻付きでリングバッファへ複製。AI音声のPCM（24kHz）は16kHzへリサンプルして供給（再生系の既存リサンプル資産を流用）
- 適用点: `_run_from_mic` のコールバックで、マイクフレームに対しAECを通した出力を**STT送信キューにのみ**流す。声紋用の `asr_pcm_buf` は生音声のまま（二股）。※buf のms整合に注意——STTのタイムスタンプは AEC 経路の音声に対応するため、既存の `cur_ms→asr_pcm_buf` 切り出し（声紋用）とのずれが±数十ms生じ得る。フレーム単位で同期して複製すればずれゼロにできる（同一コールバック内で分岐するだけ）
- 遅延・クロック: 適応フィルタが再生→マイクの遅延と部屋の伝達関数を推定する。参照供給が途切れた場合（再生なし区間）はパススルー
- ダブルトーク: AECの残差抑圧（NLP）を**弱め**に設定（人間音声の削れ最小化を優先。エコー残りは下流3層が拾う）

## 検証（受け入れ基準）

1. 配管検証: AI発話のみ区間で AEC後WAVのエネルギーが生WAV比で大幅減（>20dB目安）、人間発話のみ区間でSTT文字一致率が生と同等（WER劣化1pt以内）
2. 効果検証: AI発話と人間発話を意図的に重ねたテストセット（scripts/make_overlap_testset.py 拡張）で、AEC ON時の (a) AI混入text率の減少 (b) 重なり時のSTT取りこぼし率が悪化していないこと
3. 副作用ゼロ確認: `--aec` なし実行の全挙動が完全不変（全テスト＋実機1セッション）

## 明示的な非目標
