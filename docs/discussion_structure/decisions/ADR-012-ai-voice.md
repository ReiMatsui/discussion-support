# ADR-012: AI の声は GPT-Live。構造の正本は本システムが持つ

- 状態: 採用
- 日付: 2026-10-05
- 関連仕様: [10_ai_voice.md](../spec/10_ai_voice.md)

## 背景

区切りでの AI の声（まとめ、未応答の懸念、脱線、確認、問い合わせへの答え）をどう実現するか、
また AI（GPT-Live）から見た議論構造をどう設計するかを決める必要があった。高田から、参加者に話しかける
AI として GPT-Live を使う方針が示された。

## 選択肢

| 論点 | 選択肢 | 決定 |
|---|---|---|
| 話す層 | Realtime API ／ GPT-Live | **GPT-Live**（`main` に試験導入済み） |
| いつ・何を言うかの判断 | GPT-Live に任せる／既存の Controller と構造が決める | **Controller と構造が決める** |
| 構造の持たせ方 | 構造の要約を常に GPT-Live に読ませる／介入ごとに自己完結の指示を渡す | **介入ごとに自己完結** |
| 問い合わせへの答え | GPT-Live が自分で答える／本システムが構造から答えを作る | **本システムが作る**（委任） |
| 未応答の懸念 | 議論の途中で伝える／まとめの段階に回す | **議論の途中で伝える**（高田の判断） |

## 理由

- **既存の役割分担を守る**: 既存の設計（Rei の `live_native_plan_2026-09.md`）は、「いつ・誰に・何を」
  を決める層（Controller、規則による判定）と話す層を分けている。話す層が全二重モデルに変わっても
  判断の層は変わらないことが、設計の主張になっている。本設計も介入の種類を追加するだけにする。
- **GPT-Live の制約**（`gpt_live_api_2026-09.md` の実測）: 指示文は開始時に固定され、文脈の窓が小さく、
  受け取った文脈をどう保持・破棄するかが外から見えない。構造の要約を読ませ続けると、古い構造を
  覚えたまま話す危険がある。そのため、構造の正本は本システムが持ち、介入ごとに必要な部分だけを
  自己完結の指示で渡す。
- **画面と声を一致させる**: GPT-Live が話してよいのは画面に出ている情報とその理由だけにする。
  介入の根拠が画面で見えるため、介入の透明性（RESEARCH.md の RQ3）につながる。
- **誤った内容を作らせない**: 問い合わせへの答えと介入の指示は、構造から決まった手順で作る（LLM を
  使わない）。GPT-Live が議論の状態を推測して答えることを防ぐ。
- **未応答の懸念を途中で伝える**: 議論を深める効果を狙う（RESEARCH.md の H2「未応答の反論の回収」。
  presentation_policy.md の「未応答の攻撃」と同じ考え方）。

## 影響

- 現在の実装（`agents/_live.py`）は委任に「追加処理は不要」と返しているため、委任の処理を新たに作る。
- GPT-Live が期待どおりに委任するか、指示の制約を守るかは実測で確かめる。
- Controller への介入の種類の追加は、Rei との調整が必要になる。
