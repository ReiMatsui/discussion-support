# ADR-006: 発話ごとの判定専用モデル（速い層）と LLM（遅い層）に分ける

- 状態: 採用（使うモデルは未選択）
- 日付: 2026-10-01（構成）、2026-10-02（外部モデルへの送信の確認）、2026-10-06（判定項目）
- 関連仕様: [03_utterance_judgement.md](../spec/03_utterance_judgement.md)

## 背景

発話から焦点・ノード・立場・状態を判定する処理を、どう組むかを決める必要があった。QUD 試作は
3 発話または 5 秒待ってまとめて LLM に送り、構造化出力を得ていた。

## 選択肢

| 案 | 内容 | 問題 |
|---|---|---|
| A. 数発話ずつまとめて LLM（QUD 試作） | 構造化出力で全項目を得る | 待つだけで最大 5 秒。出力が揺れる |
| B. 発話ごとに LLM | 毎回 LLM | 遅延とコストが大きい |
| **C. 発話ごとの判定専用モデル＋規則＋必要時だけ LLM** | 選択肢と確率を速く返すモデルで判定し、規則で決める。ラベル生成だけ LLM | 判定専用モデルの日本語精度が未知 |

## 決定

C を採用する。判定部分は「選択肢と確率を返す」共通のインターフェースにし、Jev（TypeSafe AI）、
Decisions API（OpenAI）、通常の LLM ＋ 対数確率を差し替えられるようにする。日本語の会議データで
比較してから選ぶ。

## 理由

- **遅延**: 判定専用モデルは 70〜500 ms（Jev の公称値）で、発話ごとに即時に判定できる。新しい問いの
  表示まで p90 約 8 秒の見積もりに収まる（[ADR-014](ADR-014-latency.md)）。
- **確率が得られる**: 焦点の平滑化（[ADR-007](ADR-007-focus.md)）や「はっきりしたものだけ表示する」
  閾値には確率が必要である。Jev は較正された確率を返すとされる。
- **誤った内容を作らない**: 判定専用モデルは決められた選択肢から選ぶだけで文章を生成しないため、
  存在しないノードを作るような誤りが起きない。
- **役割の分離**: 文章が必要なのは新しいノードのラベルだけなので、その時だけ LLM を使う。
- 判定専用モデルは 2026 年 9 月に相次いで公開されたばかりで、日本語の精度は未知である（Jev は
  英語が主で CJK の精度が下がると明記）。そのため、差し替え可能にして比較を前提にする。
- 外部モデルへ会議内容を送ることは、研究のデータ取り扱い上問題ないことを高田が確認した。

## 影響

- 判定モデルの比較（精度・遅延・較正）がオフライン試作の最初の課題になる。
- 判定モデルの選択そのものが研究上の結果の一つになる。

## 追記（2026-10-06）: 判定項目を独立した選択問題にする

オフライン試作（Codex）で、仕様の判定項目だけでは作成規則の分岐が足りなかったため、「きっかけ」
（`trigger`）、「親」（`parent`）、「応答の対象」（`response_to`）、「乗り換えか」（`switch`）、
「是非型の決定の内容」（`decision_answer`）を追加した。各項目は決められた選択肢から1つを選ぶ独立した
問いとし、判定モデルに木の編集命令を出させない。これを仕様として採用する（[03_utterance_judgement.md](../spec/03_utterance_judgement.md) §2）。

理由: 判定モデルは選択肢を選ぶことしかしないため、規則が木を変える経路を1つに保てる。項目ごとに
確率と正解率を測れるので、どの判定が弱いかを分けて評価できる。
