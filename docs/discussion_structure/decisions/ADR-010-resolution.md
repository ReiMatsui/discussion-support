# ADR-010: 明示的な決定は自動、暗黙の決定はまとめの段階で確認する

- 状態: 採用（数値は暫定）
- 日付: 2026-10-05
- 関連仕様: [07_resolution.md](../spec/07_resolution.md)

## 背景

問いが「決定」「保留」「取り下げ」「未解決」のどれかをどう判定するかを決める必要があった。会議の
決定は明示されないことが多く、「迷ったら表示しない」原則で厳しく判定すると、画面に決定がほとんど
出ない恐れがあった。

## 選択肢と決定

| 論点 | 選択肢 | 決定 |
|---|---|---|
| 暗黙の決定 | 収束を自動で決定にする／表示しない／AI が確認して閉じる | **AI が確認して閉じる** |
| 確認の時機 | 議論の途中で定期的に（当初案: 3 分に 1 回）／まとめの段階で | **まとめの段階で**（高田の指摘） |
| 話題が移っただけの問い | 一定時間で保留にする／未解決のまま | **未解決のまま** |
| まとめに入るきっかけ | 時間のみ／時間・出尽くし・参加者の求め・議題の切替 | **4 つすべて** |

## 理由

| 知見 | 出典 | 設計への反映 |
|---|---|---|
| 会議の決定は宣言されず、やり取りの中で暗黙に成立することが多い | Huisman 2001、Fernández et al. 2008、GADR 2026 | 明示的な決定の発話だけを待つと見逃す |
| 決定の自動検出は F1 0.58（決定の区間単位） | Fernández et al. 2008 | 暗黙の決定を自動だけで確定させない |
| 提案が共同の決定になるには、聞き手の理解・同意・拘束の受け入れが要る | Stevanovic 2012 | 「誰も反対しなかった」だけでは決定にしない |
| ファシリテーターは合意の確認で決定を閉じる | Kaner 2014 | 暗黙の決定は AI の確認で閉じる |
| 区切りで要点と帰結を確かめる発話は会話の通常の実践 | Heritage & Watson 1979 | 確認は「〜で決まりでよいですか？」の形にする |

- **まとめの段階にする理由**（高田の指摘）: 議題の解決状態を確定させるのは、話題が出尽くして検討を
  終えたときか、決められた時間内で結論を出すときである。議論の途中で何度も確認するのは実際の会議の
  流れに合わない。
- **保留にしない理由**: 保留か未解決かを推測で付けると、参加者の意図と食い違う。
- **出尽くしは尋ねる**: 出尽くしは機械には確実に判定できないため、自動ではまとめに入らず、AI が
  「そろそろまとめに入りますか？」と尋ねる。
- **沈黙の扱い**: 沈黙を「異議なし」とみなすのは、AI が「異議がなければ決定とします」とその場で
  明示した場合に限る。ファシリテーションでよく使われる取り決めを、その場で成立させてから使う。

## 影響

- 会議前に終了時刻を設定する必要がある（[ADR-005](ADR-005-agenda-and-tree.md)）。
- まとめの段階は、AI の声の主要な用途になり、構造の誤りの確認もここにまとめる
  （[ADR-012](ADR-012-ai-voice.md)）。
- 議論の途中では、画面の「決定」は明示的なものだけになる。
