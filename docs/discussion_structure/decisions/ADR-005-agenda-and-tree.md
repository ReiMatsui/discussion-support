# ADR-005: 議題を根にし、小項目は置かず、次の議題は新しい木。深さは表示で縮める

- 状態: 採用（議題の「修正」と「次の議題へ」の操作の分け方は未確認）
- 日付: 2026-10-05
- 関連仕様: [02_data_model.md](../spec/02_data_model.md)、[09_display.md](../spec/09_display.md)

## 背景

木の根を何にするか、議題をどう設定するか、議題が変わったときと、木が深くなったときにどう扱うかを
決める必要があった。

## 選択肢と決定

| 論点 | 選択肢 | 決定 |
|---|---|---|
| 根 | 根なし（QUD 試作）／議題を根にする | **議題を根にする** |
| 議題の小項目 | 事前に問いとして置く／置かない | **置かない** |
| 次の議題へ移る | 根のラベルを変える／新しい木を作る | **新しい木を作る** |
| 深さ | データで制限する（深い問いを兄弟にする）／データは制限せず表示で縮める | **表示で縮める** |
| 会議前の設定 | 議題のみ／議題と終了時刻 | **議題と終了時刻** |

## 理由

- **議題を根にする**: EchoMind の焦点自動切替が失敗した主因は「LLM が会話の上位構造や議題の流れを
  把握していないこと」とされる。根の議題と焦点までの経路を常に渡すことで、この弱点に対処する。
  既存の脱線検知も議題を軸にしており、同じものを共有できる。
- **小項目を置かない**（高田の指摘）: 会議前の準備の負担が増え、操作者なしの考え方と合わない。
  話されなかった小項目が空のノードとして残る。「応答があって初めてノードにする」原則と矛盾する。
- **次の議題は新しい木**（高田の指摘）: 議題を変えることは別のことを検討し始めることであり、前の
  議題のノードは邪魔になる。前の木は記録として残し、参照・再表示できるようにする。
- **深さは表示で縮める**（高田の判断）: データで制限すると本当の親子関係が失われる。表示で焦点の
  周辺 3 段だけを見せ、上位を1行の経路に縮めれば、構造を正確に保ったまま画面を浅くできる。
  縮め方は焦点の移動時にだけ変わるため、不意に構造が変わる印象を与えない。
- **終了時刻**: 解決状態はまとめの段階で確定させる（[ADR-010](ADR-010-resolution.md)）ため、
  時間によるまとめのきっかけに使う。

## 影響

- 議題の修正（仮の議題を直す）と次の議題へ移ることを、UI の別操作に分ける必要がある（未確認の提案）。
- UI を操作しないまま次の議題に移った場合は脱線として検知されるため、AI が「議題を切り替えますか？」
  と確認する経路が要る。
