# ADR-008: ノードは「付ける」が基本。暗黙の問いは応答を待って作る

- 状態: 採用（数値は暫定）
- 日付: 2026-10-05
- 関連仕様: [05_nodes.md](../spec/05_nodes.md)

## 背景

発話からいつ・どのノードを作り、木のどこに付けるかを決める必要があった。作りすぎると重複と雑多な
ノードで画面が埋まり、作らなすぎると議論の構造が見えない。

## 選択肢

| 論点 | 選択肢 | 決定 |
|---|---|---|
| 既定の動作 | 発話ごとにノードを作る（MeetMap）／既存ノードに付けるのを基本にする | **付けるのが基本** |
| 暗黙の問い（単独の提案・問題の提示） | すぐ作る／他の参加者の応答を待つ | **応答を待つ** |
| 既存か新規か迷った場合 | 新規に倒す／既存に倒す | **既存に倒す** |
| 配置 | 自由に選ぶ／焦点に近いほど起きやすくする | **焦点に近いほど起きやすくする** |
| 深さ | 制限する／制限しない | **データは制限しない**（[ADR-005](ADR-005-agenda-and-tree.md)） |

## 理由

| 知見 | 出典 | 設計への反映 |
|---|---|---|
| 実会議で決定に関わる発話は全体の約 4%（問いの提示 1% 未満、解決案約 1%、同意約 2%） | Fernández et al. 2008（AMI） | ほとんどの発話は新しいノードを作らない。「付ける」を既定にする |
| 提案は、聞き手の応答（理解・同意・拘束の受け入れ）を経て共同の事柄になる | Stevanovic 2012 | 誰も拾わなかった提案は議論の構造に入っていないとみなし、応答を待つ |
| 1 発話から複数ノードを作ると、往復の議論で重複が増える | MeetMap | 作る前に既存ノードとの同一性を確かめる |
| 案は既存の案を参照して「更新か新規か」を決める。焦点から遠い問いの生成は注意を散らした | EchoMind | 新規作成は控えめにし、配置は焦点の近くを優先する |
| 対話マッピングの書記は、暗黙の問いを見つけて明示し、図を参加者に確認しながら進める | Conklin | 自動では確認できないため、他の参加者の応答を確認の代わりにする |

- **既存に倒す理由**: 重複ノードは後から自動で統合できない（R3）が、付け間違いは立場の印が1つ
  ずれるだけで済む。
- **明示的な問いはすぐ作る理由**: 全員に向けて答えを求めているので、すでに共同の事柄である。
- **同一性の基準**: 問いは「同じ答えで解決されるか」（QUD の考え方）、案は「同じ行動・選択を
  指すか」で判定する。条件や程度の違いは同じ案にまとめる（ノード数を抑えるため）。

## 影響

- 暗黙の問いは、応答の発話の終わりを起点に遅延を測る（[ADR-014](ADR-014-latency.md)）。
- 応答待ちの時間（60 秒）と、既存に倒す確率の幅は実データで決める。
- 懸念の中身が話題になったときに子の問いを作る規則は、立場の設計（[ADR-009](ADR-009-stances.md)）と
  連動する。
