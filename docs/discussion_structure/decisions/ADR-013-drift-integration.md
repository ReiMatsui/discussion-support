# ADR-013: 脱線検知は Rei の既存実装と統合する

- 状態: 採用（統合の方法と時期は未決）
- 日付: 2026-10-05
- 関連仕様: [08_drift.md](../spec/08_drift.md)

## 背景

「議論と無関係な発話が続く」状態は議論の問題であり、警告すべきだが、そもそも検知できるかが
問われた。調べたところ、`origin/feat/live-native`（Rei）に脱線を「議題外の話が続いた時間」で測る
仕組みがすでにあった（2026-09-14）。

## 選択肢

| 案 | 内容 |
|---|---|
| A. 本設計で別の脱線検知を作る | 焦点判定の「無関係」から独自に判定する |
| **B. 既存実装と統合する** | 速い層の判定を既存の `on / aside / off` に対応させ、同じ状態機械に渡す |

## 決定

B を採用する。判定器を二重に持たない。Rei のブランチは変更せず、本ブランチ側で状態機械を取り込むか、
統合時に Rei と調整する（高田の指示）。

## 理由

- **検知できるか**: 一発話ごとの判定は曖昧だが、「無関係な話が続いている状態」は検知しやすい。
  本当の脱線は続くが、判断に迷う一発話は続かないためである。既存実装の「続いた時間で測る」方式は
  これに合う。
- **誤検知を重く見る**: 議題に関係するが木にまだない論点（「そもそも予算って誰が決めるの？」）を
  脱線と判定してはいけない。複雑な問題の議論では一見無関係な話が隠れた側面を明らかにすることが
  あり（Conklin）、課題から外れた会話には関係を強める役割もある。既存実装の「迷ったら aside」は
  この方針に合う。
- **二重化を避ける**: 同じ会議に2つの脱線判定があると、介入が重複したり矛盾したりする。
- 話題が明確に決まった試験の回答では話題外の検出は F1 90% 前後に達する（Interspeech 2017・2019）が、
  自由な議論は条件が難しい。既存実装の精度は未測定のため、評価が必要である。

## 影響

- 既存実装の検知精度（検知の遅れ、誤警告、寄り道の誤判定）を評価する必要がある。
- 議題外の経過時間を画面に出す閾値（脱線介入の 45 秒と揃えるか）は未決。
