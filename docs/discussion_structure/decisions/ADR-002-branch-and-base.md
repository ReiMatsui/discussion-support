# ADR-002: QUD 試作と分けた新しい設計にし、`main` を土台にする

- 状態: 採用
- 日付: 2026-10-01（新しい設計として分ける）、2026-10-05（実装の土台を `main` にする）
- 関連仕様: [12_implementation.md](../spec/12_implementation.md)

## 背景

Codex が作った QUD 試作（`codex/qud-inquiry-observe`、約 9,700 行）は `main` に取り込まれず、
ローカルの `main` だけに乗っていた。新しい目的（参加者への提示）に合わせて、QUD 試作を拡張するか、
別の設計にするかを決める必要があった。実装の土台についても、`main` と、話す層を一本化している
`origin/feat/live-native`（Rei）のどちらにするかを決める必要があった。

## 選択肢

| 案 | 内容 |
|---|---|
| A. QUD 試作を拡張する | `takada/qud-inquiry` の上に作る |
| B. `main` から新しく作り、QUD 試作は参照・部分移植 | 設計を独立させる |
| 土台 1. `main` | GPT-Live の試験導入あり |
| 土台 2. `origin/feat/live-native` | 話す層の一本化・脱線の再設計を含む。未マージ |

## 決定

- B: `main` から `takada/discussion-structure` を作り、QUD 試作は参照用に残す。
- 実装の土台は `main`。`feat/live-native` の変更は、Rei のマージ後に取り込むか、必要な部分を
  移植する。Rei のブランチは変更しない。

## 理由

- QUD 試作とは前提が大きく違う（観測のみ → 提示、問いのみ → 問いと案、数発話ずつの LLM →
  発話ごとの判定、自由な更新 → 許可した変更のみ）。拡張すると不要な部分を多く抱える。
- 一方で、入力の振り分け、安定話者 ID と遡及訂正、遅延計測、保存形式などは再利用できるため、
  部分的に移植する。
- `main` には GPT-Live がある程度入っているため、それを主軸にできる（高田の判断）。共同研究者の
  未マージのブランチに依存しないため、作業を独立に進められる。

## 影響

- `feat/live-native` がマージされた時点で、話す層と脱線検知の取り込みが必要になる。
- QUD 試作は GitHub の `main` に入っていない。移植する部分はレビュー可能な単位で取り込む。
