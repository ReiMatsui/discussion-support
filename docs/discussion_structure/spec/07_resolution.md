# 07. 解決状態とまとめの段階

関連する設計判断: [ADR-010](../decisions/ADR-010-resolution.md)

## 1. 状態ごとの判定【合意】

| 状態 | 自動で付ける条件 | まとめの段階で付ける場合（§3） |
|---|---|---|
| 決定 | 明示的な決定の発話（「じゃあ紙で決まり」「それでいこう」）があり、決定を言った人以外の同意が1件以上あり（§1.1）、決定に反する立場が残っておらず（§1.2）、直後 **10 秒**に異議がない | 決定候補を AI が確認し、肯定の応答があり異議がない |
| 保留 | 明示的な保留の発話（「これは後で」「持ち帰りにしよう」） | 未解決の問いを「持ち帰り」と答えた |
| 取り下げ | 明示的な取り下げの発話（「この案はなしで」） | — |
| 未解決 | 上のどれにも当たらない（既定） | — |

### 1.1 同意として数えるもの【合意】

| 決定の内容 | 同意として数えるもの |
|---|---|
| する（是非型の「する」、選択型・自由回答型の採用） | ① 決定の発話の後の、別の人の明示的な同意。② **決定の発話より前**の、別の人の採用する案への賛成。ただし、その問いが焦点になってから（同じ話の流れの中で）出たものに限る |
| しない（是非型の「しない」） | 決定の発話の後の、別の人の明示的な同意だけ。決定より前の懸念は数えない（懸念には条件付きの賛成も含まれるため） |

- 「明示的な同意」は、速い層の判定項目「決定の内容への明示的な同意か」（`agreement`）が「はい」で、
  確率が閾値（立場と同じ 0.8）以上の発話を指す（[03_utterance_judgement.md](03_utterance_judgement.md) §2）。
  元の提案への立場（賛成・懸念）とは別に判定する。例えば「しない」決定の後の「うん、そうしよう」は、
  立場は「なし」、同意は「はい」になり、元の提案への賛成の印は付かない。
- 話題が一度移った後の古い賛成は数えない。
- 同意の「別の人」は、話者が確定しているか、話者分離のクラスタが決定を言った人と異なることが
  分かる場合に限る（[06_stances.md](06_stances.md) §6）。
- 決定の内容（する／しない、採用した案）と根拠（決定の発話、同意した人）は、立場とは別に記録する
  （[02_data_model.md](02_data_model.md) §5）。立場の印は決定後もそのまま残す。

### 1.2 決定を止める立場【合意】

決定に反する立場が残っていて、その人が決定の後に明示的に同意していない場合は、自動では決定せず
決定候補にする（§2）。「する」と「しない」で対称に扱う。

| 決定 | 決定に反する立場 | その人が決定の後に明示的に同意した場合 |
|---|---|---|
| する | 採用する案への**懸念** | 止めない（「懸念はあるが、それでいい」＝留保つきの支持） |
| しない | 元の提案への**賛成** | 止めない（「やりたかったが、やめることに同意」） |

- 「しない」決定では、元の提案への懸念は決定を止めない（懸念は「しない」側の立場であるため）。
- 黙っている人の意向は推測しない。止まった決定はまとめの段階で AI が確認する（例:「紙ストローは
  やめることで決まりでよいですか？A さんは賛成されていましたが」）。

- 話題が移っただけの問いは**保留にしない**。未解決のまま残す。
- 議論の途中で、決定の確認を AI が定期的に行うことはしない。

## 2. 決定候補【合意】

画面には出さず、まとめの段階で確認する材料にする。

- 明示的な決定の発話はあるが、決定に反する立場が残り、その人が決定の後に同意していない（§1.2）
- 明示的な決定の発話はないが、ある案への立場がすべて賛成で懸念がなく、焦点がその問いから離れた
  （収束して次へ進んだ）

## 3. まとめの段階【合意。数値は暫定値】

問いの解決状態を確定させるのは、議論の途中ではなく**会議（またはその議題）のまとめの段階**で
ある。まとめは、話題が出尽くして検討を一通り終えた場合か、決められた時間内で結論を出す場合に
行われる。

**まとめに入るきっかけ**

| きっかけ | 内容 |
|---|---|
| 時間 | 会議前に設定した終了時刻の **5 分前** |
| 出尽くし | 新しい問い・案が **3 分**出ず、立場の変化も止まり、同じ内容の繰り返しが増えた。推測なので自動では入らず、AI が「そろそろまとめに入りますか？」と尋ねる |
| 参加者の求め | 「そろそろまとめよう」「まとめて」 |
| 次の議題へ移る | UI で次の議題へ移るとき、その議題をまとめる |

**進め方**

1. 決まったことを短く読み上げる。
2. 決定候補を一つずつ確認する。懸念が残っていれば懸念を名指しする（「B さんの費用の懸念が
   残っていますが、紙で決まりでよいですか？」）。
3. 未解決の問いを伝え、今回決めるか持ち帰るかを尋ねる（持ち帰りなら保留）。
4. システムが疑った構造の誤り（構造提案）があれば、ここで確認する。
5. 時間が限られている場合は、根に近い問いから扱い、残りは未解決・持ち帰りとして一覧に残す。

例:

```text
AI: そろそろまとめます。決まったのは、ストローは紙、容器は回収制です。
AI: 告知はポスターで決まりでよいですか？
A:  はい
AI: B さんの費用の懸念が残っていますが、紙で大丈夫ですか？
B:  補助金が出るなら大丈夫です                 → B の立場を 懸念 → 賛成
AI: 回収の頻度はまだ決まっていません。今回決めますか、持ち帰りますか？
C:  持ち帰りで                                 → 保留
```

**確認への応答の扱い**

- AI の問いの直後の「はい」「うん」「そうですね」は、**肯定の答え**として扱う（話の最中の相槌とは
  扱いが異なる）。
- 他の参加者の沈黙は、AI が「異議がなければ決定とします」と**その場で明示した場合に限り**
  異議なしとみなす。
- 否定・異議があれば決定にせず、通常の議論として扱う。

**画面**: まとめの段階では、画面を「決まったこと・決定候補・未解決」の一覧に切り替えてよい
（[09_display.md](09_display.md)）。

## 4. 決定の再開【合意】

決定後に明示的に蒸し返す発話（「さっきの決定だけど、やっぱり…」）があり、他の参加者が応答
したら、未解決に戻す。蒸し返しの候補は、暗黙の問いと同じく **60 秒**応答がなければ消す。

## 5. 表示【合意】

- 是非型の決定は「決定: する」「決定: しない」と表示する。
- 選択型・自由回答型は採用された案を目立たせ、採用されなかった案は薄く表示する（消さない）。
- 明示的な決定は「見れば分かる程度」に目立たせる。
