# 03. 発話ごとの判定

関連する設計判断: [ADR-006](../decisions/ADR-006-judgement-layers.md)

## 1. 速い層と遅い層【合意】

| 層 | 担当 | 実行のタイミング | 使うもの |
|---|---|---|---|
| 速い層 | 決まった選択肢から選び、確率を返す判定 | 確定した実質発話ごと | 判定専用モデル（§3） |
| 規則 | 確率から焦点・ノード・立場・状態を決める | 速い層の直後 | 本システムの決定的な処理 |
| 遅い層 | 新しいノードのラベルと答えの型を作る | 新しいノードを作るときだけ | LLM |

## 2. 速い層の判定項目【合意】

確定した実質発話ごとに、次をまとめて確率つきで判定する（判定専用モデルは複数の問いを1回で
並列に判定できる）。

| 判定（実装上の名前） | 選択肢 | 結果の使い道 |
|---|---|---|
| どの問い・案についての発話か（`target`） | 焦点の周辺の既存ノード、新しい問い、新しい案、無関係 | 焦点（[04](04_focus.md)）、ノード（[05](05_nodes.md)） |
| 新しい内容のきっかけ（`trigger`） | 全員への明示的な問い、提案、問題の提示、懸念の中身の話題化、事実確認、なし | 作成のきっかけ（[05](05_nodes.md) §2） |
| 新しいノードの親（`parent`） | 焦点の周辺の既存ノード、焦点 | 配置（[05](05_nodes.md) §6） |
| 立場（`stance`） | 賛成、懸念、なし | 立場（[06](06_stances.md)） |
| 新しい案が既存の案の代わりか、追加か（`alternative`） | 代わり、追加 | 格上げ（[05](05_nodes.md) §5） |
| 乗り換えか（`switch`） | 既定、両方に残す、乗り換え | 立場の更新（[06](06_stances.md) §4） |
| 応答の対象（`response_to`） | 応答待ちの候補・懸念・蒸し返しのいずれか、なし | 応答待ちの作成、懸念、再開（[05](05_nodes.md)、[07](07_resolution.md)） |
| 話題転換の合図を含むか（`shift`） | はい、いいえ | 焦点（[04](04_focus.md)） |
| 議題と無関係か（`relevance`） | on、aside、off | 脱線（[08](08_drift.md)） |
| 解決に関わる発話か（`resolution`） | 決定、保留、取り下げ、異議、蒸し返し、なし | 解決状態（[07](07_resolution.md)） |
| 是非型の決定の内容（`decision_answer`） | する、しない | 解決状態（[07](07_resolution.md) §1.1） |
| 訂正の指摘か（`correction`） | 自分の立場の訂正、統合の指摘、なし | 訂正（[10](10_ai_voice.md)） |

各判定は、決められた選択肢から1つを選ぶ独立した問いにする。判定モデルに木の編集命令を出させる
ことはしない（オフライン試作で採用した形。2026-10-06 合意）。

相槌（既存のライブ基盤の判定）、AI ファシリテーター・AI パートナーの発話は判定の対象にしない。
ただし、まとめの段階で AI が確認の問いを発した直後の発話は、答えとして判定する
（[07_resolution.md](07_resolution.md)）。

## 3. 判定に使うモデル【検討中: 日本語データで比較してから選ぶ】

| 候補 | 特徴 | 懸念 |
|---|---|---|
| Jev（TypeSafe AI、`jev-1.13.0`） | 是非・選択・スコアの判定。較正された確率を返す。70〜500 ms。入力 64k トークン（状態 32k）。文章は生成しない | 主な学習言語は英語。日本語を含む CJK は精度が下がると公式に明記 |
| Decisions API（OpenAI、GPT-6 Luna） | 同種の判定 API。約 150 ms と報道 | 2026-09-29 から限定プレビュー。仕様・価格は未公開 |
| 通常の LLM ＋ 対数確率（OpenAI、現行） | 既存の契約の範囲内。選択肢を1トークンにすれば確率が得られる | 遅延が大きい。確率の較正は保証されない |

- 判定部分は「選択肢と確率を返す」共通のインターフェースにして差し替えられるようにする。
- 比較では、精度、遅延、確率の較正（確率と実際の正解率が合っているか）を測る。
- これらの外部モデルへ会議内容を送ることは、研究のデータ取り扱い上問題ない（高田確認済み）。

## 4. 入力の範囲【合意】

速い層・遅い層ともに、毎回渡すのは次だけとし、構造全体は渡さない。

- 議題（根）から焦点までの経路
- 焦点の部分木（ラベルと状態）
- 焦点以外の未解決 Issue のラベル（移動先・親の候補として）
- 直近の発話文脈と、判定対象の発話（遅い層は作成するノードの根拠発話）
