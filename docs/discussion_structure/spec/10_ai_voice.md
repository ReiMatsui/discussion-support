# 10. AI ファシリテーターの声

関連する設計判断: [ADR-012](../decisions/ADR-012-ai-voice.md)

## 1. 構成【合意】

話す層には GPT-Live（`gpt-live-1`）を使う。`main` に試験導入済み（`src/das/asr/live/agents/_live.py`）。
既存の役割分担をそのまま使う。

```text
議論構造（本設計）→ 介入候補（種類・内容・対象ノード）
  → FacilitationController（既存。規則で「どれを・今・言うか／黙るか」を決める）
  → GPT-Live（話すことに専念。割り込まれたときの停止・再開はモデルに任せる）
```

- 「いつ・何を言うか」は構造と Controller が決め、GPT-Live は伝えるだけにする。
- 本設計の介入は、Controller の種類別の採否ポリシー（優先度・待つ間・間隔・期限）に**種類を
  追加する**形にし、既存の規則は変えない。

GPT-Live の制約（`gpt_live_api_2026-09.md` の実測より）:

- 指示文と声は会議の開始時に固定され、変えられない。個々の介入は `instructions.append`
  （500 トークンまで）で指示する。
- 文脈の窓が小さい。
- 指示から声が出るまで 0.5〜4.6 秒。古くなった介入は Controller の期限で捨てる。
- 直接呼びかけられたときは、GPT-Live が自分で短く答える。

## 2. AI が話す場面【合意】

| 場面 | きっかけ | 時機 |
|---|---|---|
| まとめ | [07_resolution.md](07_resolution.md) のきっかけ | まとめの段階 |
| まとめに入る確認 | 出尽くしの兆候 | 区切り |
| 脱線 | 既存の脱線検知（[08_drift.md](08_drift.md)） | 区切り |
| 議題の切替の確認 | 脱線が続き、内容が新しい議題らしい | 区切り |
| 未応答の懸念 | 懸念に誰も応じないまま焦点が移った | 議論の途中の区切り |
| 問い合わせへの答え | 「いまどこまで決まった？」 | すぐ |
| 訂正の受け付け | 参加者が誤りを指摘した（§3） | すぐ、短く |

## 3. 訂正【合意】

- **参加者が自分から指摘した訂正は、その場で反映する**（「私は賛成じゃないよ」→立場を更新、
  「その2つは同じ話だよ」→統合）。AI は「はい、直しました」と短く受ける。
- **システムが疑った誤り（構造提案）は、議論の途中では尋ねない**。まとめの段階または議題の
  切替のときに確認する。

## 4. 言い方の規則【合意】

- 1回の発話は 1〜2 文、長くても約 10 秒（60〜80 字）。
- 画面のノードのラベルをそのまま使う。
- 内容について意見を言わない（どの案がよいかを言わない）。
- 人の名前は、話者が確定している場合だけ出す。

## 5. 頻度と優先順位【合意】

- 議論の途中に AI が自分から話すのは、脱線、未応答の懸念、議題の切替の確認、まとめに入る確認
  だけとし、既存の間隔の規則（global cooldown）に従う。
- 未応答の懸念は1つにつき1回まで伝え、まとめの段階で未解決なら再度触れる。
- 参加者からの問い合わせと訂正は、間隔の規則の対象外とする。

## 6. GPT-Live に渡す情報【合意】

原則:

1. **構造の正本は本システムが持ち、GPT-Live には持たせない**。毎回の指示を自己完結にする。
2. **GPT-Live が話してよいのは、画面に出ている情報とその理由だけ**。例外はまとめの段階の
   決定候補で、このとき画面も一覧に切り替わる。
3. **構造の状態を GPT-Live に推測させない**。決定・立場・統合は本システムが判断する。
4. **AI の確認待ちの状態は本システムが持つ**。直後の「はい」を答えとして解釈するため。

渡す情報:

| 種類 | 送り方 | 内容 |
|---|---|---|
| 開始時に固定する指示 | セッション開始時の指示文 | 役割、言い方の規則、「議論の状態を聞かれたら必ず委任する」「指示なしに話さない」「名前は指示にあるものだけ使う」 |
| 介入ごとの指示 | `instructions.append` | 種類、議題、いまの問い、対象ノードと理由、呼んでよい名前、言うこと、守ること。構造から決まった手順で作る（LLM で作らない） |
| 問い合わせへの答え | 委任（client）→ `commentary.append` | 構造から決まった形の文で作る（LLM を使わない） |

- 構造全体の要約を `thinking.append` で常に渡す方式は、古い要約が残る危険があるため既定にしない。
- 現在の実装（`agents/_live.py`）は委任に「追加処理は不要」と返しているため、委任の処理は新たに
  作る。

介入ごとの指示の例（未応答の懸念）:

```text
【介入: 未応答の懸念】
議題: 学食の環境対策
いまの問い: 「紙ストローの費用は誰が持つか？」
対象: 案「紙ストロー」への鈴木さんの懸念（理由: 費用が高い）。この懸念に応じた発話はまだない。
呼んでよい名前: 鈴木さん
言うこと: 鈴木さんの懸念がまだ話されていないことを、全員に向けて1文で伝える。
守ること: 案の良し悪しを言わない。ラベルは「」内のまま使う。60字以内。
```

問い合わせへの答えの例:

```text
（参加者）いまどこまで決まった？
（答え）決まったのは「容器を回収制にする」です。いまは「紙ストローの費用は誰が持つか？」を
話しています。未解決は「告知はどうするか？」です。
```

## 7. 実測で確かめること

- 議論の状態を聞かれたとき、GPT-Live が自分で答えずに委任するか
- 介入ごとの指示の文字数制限と「意見を言わない」を守るか
- 委任から答えの声が出るまでの遅延
- 呼びかけ以外で GPT-Live が話し出さないか（既存の確認項目）
