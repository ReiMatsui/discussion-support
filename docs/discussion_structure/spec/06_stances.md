# 06. 立場（賛成・懸念）

関連する設計判断: [ADR-009](../decisions/ADR-009-stances.md)

原則: **立場がはっきりした場合だけ印を付ける**。印は名前つきで全員に見えるため、誤った印は
印がないことより害が大きい。

## 1. 値の意味【合意】

- 値は**賛成**と**懸念**の2つ。
- **懸念**は反対に限らず、**まだ解消されていない懸念がある状態**を表す。条件付きの賛成も含める。
- 1人の立場はノードごとに1つ。是非型は問い自体に、選択型・自由回答型は各案に付ける。

## 2. 手がかりと判定【合意】

| 発話 | 判定 |
|---|---|
| 「賛成」「それでいこう」「いいと思う」「それいいね」 | 賛成 |
| 「うん」「はい」「なるほど」「そうですね」（単独） | なし（相槌） |
| 「そうですね、ただ…」「いいと思う、でも高くない？」 | 懸念（同意の前置き＋逆接） |
| 「ちょっと難しいかも」「検討が必要かな」 | 懸念（遠回しな不同意） |
| 「反対」「それはない」 | 懸念 |
| 「それってお金かかりすぎじゃない？」 | 懸念（問いただす質問・反語） |
| 「それっていくらかかるの？」 | なし（情報を求める質問） |
| 黙っている | なし（沈黙から同意を推測しない） |
| 案を出した本人 | 賛成（自動） |

ただし、まとめの段階で AI が確認の問いを発した直後の「はい」「うん」は、肯定の答えとして扱う
（[07_resolution.md](07_resolution.md)）。

## 3. 判定の方法【合意。閾値は暫定値】

- 速い層が、対象ノードと立場（賛成・懸念・なし）を確率つきで判定する。「それいいね」のように
  対象が明示されない発話は、直近に言及された案・問いを対象の候補にする。
- 立場の確率が **0.8** 以上のときだけ印を付け、閾値未満は内部に記録だけする。
- 話者が確定していれば名前つきの印、未確定なら「?」の印にする。
- AI ファシリテーターと AI パートナーの発話には印を付けない。

## 4. 更新の規則【合意】

- 本人の新しい発話で上書きする。
- 立場は**本人の発話からだけ**変える。他の人が懸念に答えても、本人が納得を示すまでは懸念のまま
  残す。
- 意見の乗り換えは頻繁に起きる前提で扱う。
  - **選択型**: 別の案に賛成したら、前の案の賛成を外す。「A も B もいい」「どっちでもいい」の
    ときだけ両方に残す。
  - **自由回答型**（案を組み合わせられる）: 追加を既定とし、「やっぱり B」「A より B」のときだけ
    前の賛成を外す。
  - 前の案に付けた懸念は、乗り換えても外さない。
- 参加者自身の訂正（「私は賛成じゃないよ」）は、その場で反映する（[10_ai_voice.md](10_ai_voice.md)）。
- 話者の遡及訂正で同じ人の印が同じノードに重なった場合は、新しい方を残す。

## 5. 懸念の扱い【合意】

- 懸念の中身（「費用が高い」）は理由として内部に保存し、画面には出さない。
- 懸念の中身そのものを他の人が話題にしたら、子の Issue を作る（[05_nodes.md](05_nodes.md)）。
- 誰も応じていない懸念は、AI が議論の途中の区切りで伝える（[10_ai_voice.md](10_ai_voice.md)）。

## 6. 話者帰属の入力【合意】

- 既存のライブ基盤（Soniox ＋ pyannoteAI ＋ ReDimNet）の話者・確信度・未確定フラグを使う。
  精度は `docs/design/STATUS.md` が正本。
- Soniox の話者ラベル単独は使わない（確信度がなく棄権できない）。
- **名前を出す閾値は、議事録より厳しくする**（合意）。AI 介入の名指しと同じ閾値（声紋の類似度
  0.5 前後。実データで調整）を使う。STATUS.md の risk–coverage では、閾値 0.42 で名指しの誤りが
  現行の半分（校正 4.2% / 持ち越し 1.5%）、被覆の代償は約 10 ポイント。閾値に届かない印は「?」で
  表示し、後から話者が確定したら名前を付ける。
- **未確定の話者の発話を「別の人」として数える条件**（合意）: 応答（[05_nodes.md](05_nodes.md) §2）や
  同意（[07_resolution.md](07_resolution.md) §1.1）で「別の人」として数えるのは、話者が確定しているか、
  話者分離のクラスタが相手と異なることが分かる場合だけ。同じ人の続きの発話が未確定になって
  「他の人の応答」と誤認されるのを防ぐ。

## 7. 表示【合意】

- **1人1つの印**を、ノード内の「賛成」の行と「懸念」の行に並べる。
- 印には名前（略記）を付ける。賛成と懸念は色だけでなく形（○ / □）でも区別する。
- 名前を出すのは話者帰属が確定している場合だけ。未確定は「?」の印。
- 賛否の割合を色のグラデーションで表す方式は採らない。
- 不一致の強調表示（「意見が分かれています」）は付けない。
