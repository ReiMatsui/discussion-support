# 08. 議論と無関係な話（脱線）の検知

関連する設計判断: [ADR-013](../decisions/ADR-013-drift-integration.md)

## 1. 既存の実装【合意: これと統合する】

`origin/feat/live-native`（Rei）の `src/das/asr/live/_drift.py` と `_DRIFT_LABEL_PROMPT`。

- LLM が直近の各発話に `on`（議題を進める）/ `aside`（役立つ寄り道・進行・相槌・冗談）/
  `off`（議題と無関係）を付ける。迷ったら `aside`。
- `off` が続いた時間を測り、標準 **45 秒**を超えたら AI が議題に戻す。戻した後も続けば
  **60 秒**あけてもう一度。誰かが議題に戻れば何もしない。
- 判定の軸は、議題と「離れる前に出ていた論点」に固定する。
- 検知の精度はまだ測定されていない。

## 2. 検知の対象【合意】

| 種類 | 例 | 扱い |
|---|---|---|
| 雑談・冗談・挨拶 | 「昨日の試合見た？」 | 短ければ問題にしない |
| 進行・段取り | 「あと 10 分です」 | 脱線ではない |
| 議題に関係するが木にまだない論点 | 「そもそも予算って誰が決めるの？」 | **脱線と誤判定してはいけない**。新しい問いの候補 |
| 議題と無関係な話が続く | 別案件の話が数分続く | 検知の対象 |

役立つ寄り道を脱線と判定する誤りを、見逃しより重く見る。

## 3. 本設計への組み込み【合意】

- 速い層の「議題と無関係か」の判定（[03_utterance_judgement.md](03_utterance_judgement.md)）を
  `on / aside / off` に対応させ、同じ状態機械（`DriftRun`）に渡す。判定器を二重に持たない。
- **Rei のブランチは変更しない**。本ブランチ側で状態機械を取り込むか、統合時に Rei と調整する。
- 脱線中の発話からはノードを作らない。
- 脱線中も焦点の表示は残す（戻る先を示すため）。焦点の近くに「議題外 1:30」のような経過時間を
  控えめに出す。強い警告は出さない。
- 議題に戻す呼びかけは AI が行う（[10_ai_voice.md](10_ai_voice.md)）。
- 脱線が続き、内容が新しい議題らしい場合は、AI が「議題を切り替えますか？」と尋ねる。
