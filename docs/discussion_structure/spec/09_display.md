# 09. 画面

関連する設計判断: [ADR-011](../decisions/ADR-011-presentation.md)、
[ADR-005](../decisions/ADR-005-agenda-and-tree.md)

## 1. 提示の構成【合意】

| 経路 | 役割 | 時機 |
|---|---|---|
| 画面（静かに常に最新） | 見返したときに「いまの問い」「決まったこと」「未解決」がすぐ分かる | 随時。ただし注意を引かない変わり方で |
| AI の声 | 全員に気づいてほしいことを伝える | 区切りだけ（[10_ai_voice.md](10_ai_voice.md)） |
| 声での問い合わせ | 「いまどこまで決まった？」に答える | 参加者が尋ねたとき |

画面は**表示専用**であり、参加者の操作を前提にしない。

## 2. 出来事ごとの知らせ方の強さ【合意】

| 出来事 | 知らせ方 |
|---|---|
| ノードの追加、立場の印の増減、焦点の移動 | 気づかれなくてよい（ゆっくり現れる・変わる） |
| 明示的な決定 | 見れば分かる程度に目立たせる |
| 脱線、未応答の懸念、確認 | 画面ではなく AI の声で区切りに伝える |

## 3. 更新の規則【合意。数値は暫定値】

- 点滅・移動・急な出現を使わない。
- 画面への反映はまとめて行い、反映の最短間隔を **3 秒**とする。
- 既存のノードの位置を動かさない。新しい子は兄弟の末尾に追加する。
- 表示する Issue の段数は焦点の周辺 **3 段**までとし、それより上は「学食の環境対策 › ストロー ›
  紙ストロー ›」のように1行の経路に縮める。縮め方は焦点が移ったときだけ変える。
- 表示ノード数の上限を **15** とし、超えたら焦点から遠い、決定済みまたは長く言及のない部分木から
  折りたたむ。折りたたみは規則で行う。
- 【検討中】処理中の表示（「更新中」）を出すか。出すなら 1 秒を超えたときだけ、目立たない形で。
- 【検討中】新しいノードの「新」印を付けるか。静かな画面の方針では付けない方がよい可能性がある。

## 4. 自動で行ってよい変更・行わない変更【合意】

自動で行ってよい:

| 変更 | 条件 |
|---|---|
| 葉としてノードを追加 | [05_nodes.md](05_nodes.md) の作成規則 |
| 立場・根拠発話の追加・更新 | [06_stances.md](06_stances.md) |
| 是非型から選択型への格上げ | 対立する案が出た場合 |
| 解決状態の変更 | [07_resolution.md](07_resolution.md) の条件 |
| 焦点の移動 | [04_focus.md](04_focus.md) の規則 |
| 部分木の折りたたみ | §3 の規則 |

自動では行わない（**構造提案**として記録し、まとめの段階で AI が確認するか、参加者の指摘で
行う）:

- ノードの削除、親の付け替え、統合（重複の解消）、ラベルの変更・分割

## 5. 画面の構成【合意】

見返したときに目に入る順に、「いまの問い」→「決まったこと・未解決」→「木の全体」とする。

## 6. 表示要素

**立場の印**【合意】: [06_stances.md](06_stances.md) §7。

**解決状態**【合意】: [07_resolution.md](07_resolution.md) §5。

**焦点と解決状態の見せ分け**【未確認の提案】: 焦点は枠と強調色、解決状態はバッジで表し、
「決定済みだが再び議論中」も表せるようにする。

**議題外の経過時間**【合意】: [08_drift.md](08_drift.md) §3。

## 7. 例外【合意】

- まとめの段階（[07_resolution.md](07_resolution.md)）では、画面を「決まったこと・決定候補・
  未解決」の一覧に切り替えてよい。
- AI が話している間は、言及しているノードを控えめに示してよい（全員が AI の声に注意を向けて
  いる区切りのため）。
