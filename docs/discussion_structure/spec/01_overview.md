# 01. 全体像

関連する設計判断: [ADR-001](../decisions/ADR-001-positioning.md)、
[ADR-011](../decisions/ADR-011-presentation.md)、[ADR-014](../decisions/ADR-014-latency.md)

## 1. 目的【合意】

> 操作者なしで動く、リアルタイムの対面議論の議論グラフ

- 対面議論の音声から、議論の構造（問いと案の木）を自動で構築する。PC を操作する書記や
  ファシリテーターを必要としない。
- 「いま何が議論されているか（焦点）」と「何が決まり何が未解決か（解決状態）」を自動で追跡する。
- 構造を見るのは、**会議の参加者全員**と **AI ファシリテーター**である。

先行研究との差分（詳しくは [related_work.md](../research/related_work.md)）:

1. **操作者なし**で、対面の音声から構造を作る（最も近い EchoMind は操作者が必要）。
2. **焦点と解決状態を自動で追跡**する（EchoMind では焦点の自動切替が実用に届かなかった）。
3. **誤って名指ししない話者帰属**（本プロジェクトの選択的話者同定）を、立場の表示に使う。
4. **注意を奪わない提示**を設計の対象にする。

## 2. 構造の構築と提示を分ける【合意】

- **構築**: 木を作り、焦点・解決状態・立場を追跡する。研究の中核であり、提示方法にかかわらず
  常に行う。
- **提示**: 人がいつ・どう構造に触れるか。「静かな画面＋区切りでの AI の声＋声での問い合わせ」
  とする（[09_display.md](09_display.md)、[10_ai_voice.md](10_ai_voice.md)）。

## 3. 処理の流れ

```text
マイク
  → Soniox（音声認識）＋ pyannoteAI（話者分離）＋ ReDimNet（声紋照合）   … 既存のライブ基盤
  → 確定した発話（本文・話者・話者の確信度）
  → 速い層（判定専用モデル。発話ごと）                                  … 03
       どの問い・案についての発話か ／ 新しい問い・案か ／ 立場 ／ 無関係か ／ 決定・保留か
  → 規則（焦点の平滑化・作成規則・状態の要件）                          … 04〜08
  → 遅い層（LLM。新しいノードのラベル生成のときだけ）                    … 05
  → 構造の正本（本システムが1つだけ持つ）
  ├→ 画面（静かに随時更新）                                            … 09
  └→ 介入候補 → FacilitationController（既存）→ GPT-Live（話す）       … 10
```

## 4. 見る主体ごとの「見え方」【合意】

構造の正本は本システムが1つだけ持ち、見る主体ごとに必要な部分を切り出す。

| 見る主体 | 見るもの | 形 | 更新 |
|---|---|---|---|
| 参加者（画面） | はっきりした立場、明示的な決定、焦点 | 図 | 静かに随時 |
| 本システムの判断部（Controller・介入候補の生成） | すべて（確率、決定候補、理由、構造提案、遷移履歴、AI の確認待ち） | データ | 即時 |
| 判定モデル（速い層・遅い層） | 焦点の周辺 | 構造化テキスト | 発話ごと |
| GPT-Live（話す AI） | その発話に必要な部分だけ | 自己完結の短い文章 | 発話ごと |

## 5. 要求

| ID | 要求 | 判定基準 |
|---|---|---|
| R1 | 操作者なしで動く | 会議中に誰も PC を操作しなくても構造が更新される |
| R2 | リアルタイムで反映する | 表示要素ごとの遅延目標（§6） |
| R3 | 構造が頻繁に変わらない | 表示済みノードの削除・移動・統合・ラベル変更を自動では行わない（[09_display.md](09_display.md) §4） |
| R4 | ノードの内容を瞬間的に理解できる | 問いのラベル ≤ 20 字、案のラベル ≤ 16 字（全角換算） |
| R5 | 焦点を自動で追跡する | 焦点の問いは常に1つ（議題の根を含む） |
| R6 | 解決状態を自動で追跡する | 決定・保留・取り下げ・未解決を区別して表示する |
| R7 | 参加者と AI ファシリテーターが同じ構造に基づく | 同じ正本から両者の見え方を作る（§4） |
| R8 | 訂正と暗黙の決定の確認は声で行う | 参加者の指摘はその場で反映し、システムが疑った誤りと決定候補はまとめの段階で AI が確認する |
| R9 | 画面は表示専用で、注意を引かない | 参加者の操作を前提にしない。点滅・移動・急な出現を使わない |

R3 の例外は、参加者の発話という明示的なきっかけがある変更（訂正の指摘、まとめの段階の確認への
応答、対立する案による格上げ）だけである。

## 6. 遅延目標【暫定値】

「その情報が役立つ時点までに出ているか」で決める（理由は [ADR-014](../decisions/ADR-014-latency.md)）。

| 表示要素 | 目標（p50 / p90） | 起点 |
|---|---|---|
| 新しい問い | 5 秒 / 8 秒 | 問いの発話の終わり（応答を待って作る問いは、応答の発話の終わり） |
| 新しい案 | 5 秒 / 8 秒 | 案の発話の終わり |
| 立場の印 | 8 秒 / 15 秒 | 立場を示した発話の終わり |
| 明示的な決定 | 8 秒 / 15 秒 | 決定・同意の発話の終わり |
| 焦点の切替 | 15 秒 / 25 秒 | 注釈上の移行時刻（ちらつき防止の待ちを含む） |

処理の内訳の見積もり（実測で置き換える）:

| 区間 | 見積もり |
|---|---|
| 発話の終わり → 音声認識の確定 | 0.3〜2 秒（本システムでの実測なし） |
| 話者の暫定帰属 | ほぼ 0 秒（介入時点の帰属精度 85〜86%。後から遡及訂正） |
| 速い層の判定 | 0.1〜0.5 秒 |
| 遅い層のラベル生成 | 1〜3 秒 |
| 画面への反映間隔 | 0〜3 秒 |
| 合計（新しい問い） | p50 約 4 秒、p90 約 8 秒 |

## 7. 設計原則【合意】

1. **構築と提示を分ける**。構築は常に行い、提示は注意を奪わない形にする。
2. **構造の正本は本システムが1つだけ持つ**。画面・判定モデル・GPT-Live には必要な部分だけを渡す。
3. **ノードは問いと案の2種だけ**。賛否は話者の立場の属性、理由は内部だけに持つ。
4. **はっきりしたものだけを表示する**。名前つきで全員に見えるため、誤表示を見逃しより重く見る。
5. **「付ける」が基本、「作る」は例外**。発話の多くは既存ノードへの言及である。
6. **LLM は提案し、規則が決める**。焦点の切替・状態の変更・ノードの追加は、確率と規則で決める。
7. **表示済みの構造は自動で組み替えない**。組み替えは参加者の発話をきっかけにする。
8. **案が出ただけでは決定にしない**。決定には同意の証拠か、まとめの段階での確認が要る。
9. **参加者に GUI を操作させない**。訂正や確認は声で行う。
